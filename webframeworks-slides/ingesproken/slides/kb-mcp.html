MCP, het Model Context Protocol, is een open standaard die Anthropic in november 2024 introduceerde en die intussen door bijna alle AI-tools ondersteund wordt. Het lost een eenvoudig probleem op: hoe laat je een AI-agent op een uniforme manier praten met externe systemen? Vroeger moest elke AI-tool voor elk systeem een eigen koppeling bouwen: één voor GitHub, één voor je database, één voor Slack. Met MCP bouw je één MCP-server per systeem, en elke AI-applicatie die MCP spreekt, kan die gebruiken. Daarom wordt het vaak vergeleken met USB-C: één stekker voor alles. De architectuur heeft drie delen. De host is de AI-applicatie, zoals Claude Code, Cursor of VS Code; daarin zit een MCP-client. De MCP-server is een klein programma dat een systeem toegankelijk maakt. En achter de server zit het systeem zelf, bijvoorbeeld je draaiende Next.js-dev server, een database of GitHub. Een MCP-server biedt drie soorten dingen aan. Tools: functies die het model mag aanroepen, bijvoorbeeld get_errors om de huidige fouten op te vragen. Resources: data die het model kan lezen, zoals een bestand of een databaseschema. En prompts: herbruikbare sjablonen. De communicatie gebeurt met JSON-RPC, een eenvoudig formaat om functies aan te roepen met JSON-berichten. Je ziet rechtsonder hoe zo'n tool-aanroep eruitziet. Waarom is dit relevant voor web frameworks? Agents kunnen de browser niet zien. Een developer zag een fout in de browser en typte ‘fix the error’, maar de agent wist niet welke fout. Via een MCP-server, zoals next-devtools-mcp bij Next.js of de MCP-server in de Angular CLI, kan een agent de fouten, routes en build-status van je draaiende app opvragen.
