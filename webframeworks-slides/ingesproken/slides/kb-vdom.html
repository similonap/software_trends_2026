De virtual DOM

Jij schrijft JSX

<ul className="list">
  <li>Melk</li>
</ul>

Na de build

jsx('ul', {
  className: 'list',
  children: jsx('li', {
    children: 'Melk'
  })
})

Resultaat: een object

{
 type: 'ul',
 props: {
  className: 'list',
  children: {
   type: 'li',
   props: {
    children: 'Melk'
}}}}

De virtual DOM is een boom van gewone JavaScript-objecten die beschrijft hoe de UI eruit moet zien. Zo’n object aanmaken is goedkoop; de echte DOM aanpassen is duur. React maakt bij elke render een nieuwe boom en vergelijkt die met de vorige.

Kernbegrip

16

Nu kunnen we de virtual DOM uitleggen. Volg de drie stappen op de slide. Stap één: in React schrijf je JSX. Dat lijkt op HTML, maar het is geen HTML en ook geen geldige JavaScript. De browser begrijpt het niet. Stap twee: daarom zet de build tool, bijvoorbeeld Vite met de React-plugin, elke JSX-tag om naar een gewone functie-aanroep. In moderne React heet die functie jsx; vroeger was dat React.createElement. Het eerste argument is het type, hier de string ul, het tweede argument zijn de props, waaronder de children. JSX is dus syntactische suiker: een handigere schrijfwijze voor functie-aanroepen. Stap drie: wanneer je component rendert en die functie uitgevoerd wordt, krijg je een gewoon JavaScript-object terug. Dat object heeft een type, ul, en props, met daarin className en children. De children zijn op hun beurt weer zo'n object, met type li. Samen vormen die objecten een boom die beschrijft hoe de UI eruit moet zien. Die boom van objecten noemen we de virtual DOM. Het is geen kopie van de echte DOM met al zijn honderden eigenschappen en methodes, maar een lichte beschrijving met enkel type, props en kinderen. Waarom is dat nuttig? Zo'n object aanmaken is extreem goedkoop: het kost een paar nanoseconden, er gebeurt geen layout en er wordt niets getekend. React kan dus zonder probleem bij elke wijziging een volledig nieuwe virtuele boom maken. Daarna vergelijkt React de nieuwe boom met de vorige, en past enkel de verschillen toe op de echte, dure DOM. Een veelgemaakte misvatting: de virtual DOM is niet sneller dan de DOM zelf. Een perfect geschreven imperatieve DOM-aanpassing is altijd sneller, want React doet extra werk door te vergelijken. Het voordeel is dat je declaratief kan programmeren en toch een redelijk efficiënt aantal DOM-aanpassingen krijgt, zonder er zelf over na te denken.
