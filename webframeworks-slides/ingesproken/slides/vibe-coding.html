Tweede punt: vibe coding. De term werd begin 2025 gelanceerd door Andrej Karpathy, een bekende AI-onderzoeker. Het betekent: je beschrijft wat je wil, je laat de AI de code genereren en je accepteert het resultaat zonder de code zelf te lezen. Je stuurt enkel bij op basis van wat je ziet. Tools als v0 van Vercel, Lovable en Bolt maken dat toegankelijk voor mensen die zelf niet programmeren: je typt een prompt en krijgt een werkende webapplicatie, typisch met React, Tailwind en Supabase als backend. Dat is fantastisch om snel een idee te testen. Maar kijk naar de cijfers. Een onderzoeker bekeek 1.645 apps die met Lovable gemaakt waren, en ongeveer tien procent ervan had een volledig open database. De oorzaak: Row-Level Security stond niet aan. Supabase is een backend-dienst waarbij de browser rechtstreeks met de database praat. Dat is alleen veilig als de database per rij controleert wie die rij mag lezen of wijzigen: dat is Row-Level Security. Stond dat uit, dan kon iedereen met de publieke sleutel alle data lezen en aanpassen. En Veracode testte meer dan honderd taalmodellen op securitygevoelige programmeertaken: in vijfenveertig procent van de gevallen bevatte de gegenereerde code een lek uit de OWASP Top 10. OWASP is een non-profitorganisatie die een lijst bijhoudt van de tien belangrijkste beveiligingsrisico's voor webapplicaties, zoals injectie, ontbrekende toegangscontrole en zwakke authenticatie. Er circuleren veel verschillende cijfers, maar ze wijzen allemaal dezelfde richting uit. Het probleem is niet dat AI per definitie slechte code schrijft, maar dat niemand de code nakijkt, en dat de gevaarlijkste fouten vaak in configuratie zitten. Vibe coding is prima voor een prototype. Voor productie heb je engineering nodig: code review, tests en nadenken over wie wat mag.
