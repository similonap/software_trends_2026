Wat betekent dit allemaal voor jullie, als toekomstige developers? In één zin: de agent kent de API, jij moet het systeem kennen. Eén: fundamenten boven framework. Een agent kan perfect de syntax van Signal Forms of ‘use cache’ opzoeken. Wat hij niet altijd goed doet, is beslissen of iets op de server of in de browser hoort, waarom een pagina traag is, of waar een beveiligingsprobleem zit. Daarvoor moet je de begrippen uit deze les begrijpen: HTTP, de DOM, rendering-strategieën, hydration, reactiviteit, caching en security. Twee: lees de diff. Een diff is het overzicht van wat er in de code veranderd is. Behandel AI-gegenereerde code zoals code van een nieuwe collega: vaak goed, soms subtiel fout, en altijd jouw verantwoordelijkheid zodra je ze merget. Drie: ken de servergrens. Na React2Shell weten we dat dit geen detail is. Weet wat er op de server draait, wat naar de browser gaat, en welke functies publiek bereikbaar zijn. Vier: leer je agent sturen. Een goede AGENTS.md met je stack en conventies, de actuele documentatie, en tests die beschrijven wat de code moet doen. Tests zijn misschien de beste specificatie die je een agent kan geven, want hij kan ze zelf uitvoeren en zo controleren of zijn werk klopt. En vijf: blijf kritisch. Volg het geld. Kies niet het framework dat het model standaard kiest of dat een hostingbedrijf promoot, maar het framework dat past bij wat jouw applicatie nodig heeft.
