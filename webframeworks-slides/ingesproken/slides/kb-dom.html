De DOM (Document Object Model)

HTML (tekst)

<html>
  <body>
    <h1>Todo's</h1>
    <ul>
      <li>Melk</li>
      <li>Brood</li>
    </ul>
  </body>
</html>

DOM-boom (objecten)

document
└─ html
   └─ body
      ├─ h1
      │  └─ "Todo's"
      └─ ul
         ├─ li ─ "Melk"
         └─ li ─ "Brood"

JavaScript past de boom aan

const ul = document
  .querySelector('ul');
const li = document
  .createElement('li');
li.textContent = 'Kaas';
ul.appendChild(li);

De browser toont meteen een derde item.

  • De DOM is de boom van objecten die de browser uit de HTML opbouwt. Elk element is een node die JavaScript kan lezen en aanpassen.
  • Waarom duur? Na een wijziging moet de browser soms de layout herberekenen (reflow) en opnieuw tekenen (repaint).

Kernbegrip

14

Om de virtual DOM te begrijpen, moeten we eerst goed weten wat de gewone DOM is. Wanneer de browser een HTML-pagina ontvangt, is dat gewoon tekst. De browser leest die tekst, dat heet parsen, en bouwt er een boomstructuur van objecten mee op in het geheugen. Die boom heet de DOM, het Document Object Model. Kijk naar het midden van de slide: bovenaan staat het document, daaronder het html-element, daaronder body, en daaronder de h1 en de ul met twee li-elementen. Elk element, en zelfs elk stukje tekst, is een node in die boom. Een node heeft een parent, kinderen en siblings, net zoals in een stamboom. Wat de gebruiker op het scherm ziet, is een weergave van die boom. Als je de boom aanpast, past het scherm zich aan. JavaScript krijgt toegang tot de DOM via het document-object. Rechts zie je een voorbeeld: we zoeken de ul op met querySelector, maken een nieuw li-element aan, zetten er de tekst Kaas in, en hangen het aan de lijst met appendChild. De browser toont meteen een derde item. Waarom zeggen we dat DOM-aanpassingen duur zijn? Een JavaScript-object aanpassen kost bijna niets. Maar na een DOM-wijziging moet de browser mogelijk de layout opnieuw berekenen: hoe groot is elk element en waar staat het? Dat heet een reflow. Een extra lijstitem kan immers alles eronder naar beneden duwen. Daarna moeten de pixels opnieuw getekend worden: een repaint. Als je in een lus honderd keer de DOM aanpast en tussendoor afmetingen opvraagt, kan de browser honderd keer een reflow moeten doen. Dat maakt pagina's traag en schokkerig. Onthoud dus twee dingen: de DOM is een boom van objecten die de browser uit HTML maakt, en het aanpassen ervan is relatief duur door reflow en repaint. Frameworks proberen daarom zo weinig mogelijk DOM-aanpassingen te doen.
