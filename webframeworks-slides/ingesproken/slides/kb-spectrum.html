En React? Noemt zichzelf een library, maar doet IoC voor de UI. Voor een nieuwe app raadt het React-team zelf een framework aan (Next.js, React Router).

Kernbegrip

5

In de praktijk is library of framework geen ja-neevraag. De betere vraag is: hoeveel controle geef je af, en over welke delen van je applicatie? Zet je de tools op een rij, dan krijg je een spectrum. Bovenaan staat een pure library, zoals date-fns of Lodash. Die beslist niets voor jou: jij bepaalt de structuur, de flow en wat er met de DOM gebeurt. Daaronder staat React. React neemt één ding over: het renderen van de gebruikersinterface. Je roept je componenten nooit zelf aan, en je raakt de DOM niet aan. Voor dat deel is er dus inversion of control. Maar al de rest laat React aan jou over: welke URL welke pagina toont, hoe je data ophaalt, hoe je project gebouwd wordt en hoe je mappen gestructureerd zijn. Je kan React zelfs in één enkele div van een bestaande pagina inbouwen en de rest van die pagina met gewone JavaScript laten werken. Die beperkte scope is de reden waarom React zichzelf een library noemt: een library voor gebruikersinterfaces. Daaronder staat een volwaardig framework zoals Angular. Dat beslist veel meer voor jou: niet alleen de rendering, maar ook routing, formulieren, een HTTP-client, dependency injection, en conventies over hoe je project eruitziet. Jij schrijft componenten en services, en Angular roept ze aan. Vue en Svelte zitten iets lichter: ze hebben een officiële router en state-oplossing, maar leggen minder op dan Angular. Onderaan staat het meta-framework, zoals Next.js voor React, Nuxt voor Vue en SvelteKit voor Svelte. Dat bouwt verder op een UI-framework en neemt ook de rest over: de server, routing op basis van bestanden, data ophalen, de build en de deployment. Waarom bestaan meta-frameworks? Omdat het zelf combineren van tientallen tools, zoals een router, een server, een bundler, beeldoptimalisatie en TypeScript-configuratie, veel werk is en moeilijk te onderhouden. Een meta-framework maakt die keuzes voor jou. Dat is handig, maar je erft ook de keuzes van het meta-framework. Dat komt later in de les terug. En React? Het React-team zegt het eigenlijk zelf: sinds de nieuwe documentatie van 2023 raden ze aan om een nieuwe React-app te starten met een framework, zoals Next.js of React Router. Begin 2025 werd Create React App, de oude manier om een React-project zonder framework op te zetten, officieel afgeschaft. React alleen is dus een library met inversion of control voor de UI. Wie een volledige applicatie bouwt, gebruikt React bijna altijd binnen een framework. Een goede examenvraag is dus: leg uit waarom React soms een library en soms een framework genoemd wordt. Het antwoord: React doet inversion of control voor het renderen, maar laat routing, data en build aan jou over.
