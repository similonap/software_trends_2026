React Server Components (RSC)

  • Server Component (standaard in Next.js): draait enkel op de server, mag async zijn en rechtstreeks de database lezen
  • Geen state, geen events
  • Code gaat niet naar de browser
  • Client Component: gemarkeerd met 'use client', wordt op de server voorgerenderd én in de browser gehydrateerd
  • Kan state, effects en event handlers gebruiken
  • Regels:
  • Een server component mag een client component bevatten, niet omgekeerd
  • Props van server naar client moeten serialiseerbaar zijn (geen functies)

// app/page.tsx: Server Component
export default async function Page() {
  const posts = await db.post.findMany();
  return <LikeButton start={posts.length} />;
}

// LikeButton.tsx: Client Component
'use client';
export function LikeButton({ start }) {
  const [n, setN] = useState(start);
  return <button onClick={() =>
    setN(n + 1)}>{n}</button>;
}

React Server Components, afgekort RSC, zijn de grootste verandering in React van de laatste jaren, en de basis van Next.js. Het idee: niet elk component hoeft naar de browser. Een component dat enkel een lijst blogposts toont, heeft geen interactie nodig. Waarom zou je de code daarvan naar de browser sturen en hydrateren? Daarom zijn er twee soorten componenten. Een Server Component draait enkel op de server. In Next.js is dat de standaard: elk component is een server component, tenzij je iets anders aangeeft. Een server component mag een async functie zijn en mag rechtstreeks de database lezen, zoals je ziet in de code: geen API-endpoint nodig. Het resultaat wordt naar de browser gestuurd als een beschrijving van de UI, maar de code zelf gaat niet mee. Een server component kan daarom geen state hebben en niet reageren op klikken. Een Client Component markeer je met de directive ‘use client’ bovenaan het bestand. Dat is het klassieke React-component: het wordt op de server voorgerenderd naar HTML en in de browser gehydrateerd, en het kan useState, effects en event handlers gebruiken. In het voorbeeld is de LikeButton een client component, want hij moet reageren op een klik. Twee belangrijke regels. Eén: een server component mag een client component bevatten, maar een client component kan geen server component importeren, want de browser kan geen server-code uitvoeren. Twee: alles wat een server component als props aan een client component doorgeeft, moet serialiseerbaar zijn, dus omgezet kunnen worden naar tekst om over het netwerk te sturen. Getallen, strings en objecten kunnen; functies niet. Dat begrip serialisatie wordt belangrijk in trend drie. Voordelen: minder JavaScript in de browser, data ophalen dicht bij de database. Nadelen: een complexer mentaal model en meer werk op de server.
