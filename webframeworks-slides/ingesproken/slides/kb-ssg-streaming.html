Static site generation en streaming

Static site generation (SSG)

De HTML van elke pagina wordt één keer gemaakt tijdens de build en als statisch bestand bewaard.

  • Verspreid via een CDN: servers wereldwijd, dicht bij de gebruiker
  • Voordelen: zeer snel, goedkoop, weinig aanvalsoppervlak
  • Nadeel: niet voor gepersonaliseerde of snel veranderende inhoud
  • Bv. blog, documentatie, marketingsite

Streaming

De server stuurt de HTML in delen over één response: eerst een shell met placeholders, daarna de trage delen.

<Header /> // meteen
<Suspense fallback={<Spinner />}>
  <Reviews /> // later
</Suspense>

Partial prerendering = statische shell bij de build, dynamische delen streamen bij het request.

Naast CSR en SSR zijn er nog twee belangrijke varianten. Static site generation, afgekort SSG. Hier wordt de HTML niet bij elk request gemaakt, maar één keer, tijdens de build. Het resultaat zijn gewone HTML-bestanden die je op een CDN kan zetten. Een CDN, een content delivery network, is een netwerk van servers over de hele wereld die kopieën van je bestanden bewaren, zodat een gebruiker in Japan ze uit Tokio krijgt en niet uit Brussel. SSG is zeer snel, zeer goedkoop, en er draait geen server-code bij een request, wat ook veilig is. Het nadeel: als de inhoud verandert, moet je opnieuw builden, en gepersonaliseerde inhoud, zoals ‘welkom, Jan’, kan niet in de statische HTML. Streaming lost een ander probleem op. Stel dat een productpagina de productinfo snel heeft, maar de reviews uit een trage externe dienst moeten komen. Bij klassieke SSR wacht de server tot alles klaar is voor hij iets stuurt. Bij streaming stuurt de server meteen het eerste deel van de HTML, met een placeholder zoals een spinner op de plek van de reviews. Zodra de reviews klaar zijn, stuurt de server over dezelfde HTTP-verbinding het volgende stuk HTML, dat de placeholder vervangt. HTTP laat toe dat een response in stukken binnenkomt. In React markeer je zo'n traag deel met Suspense: alles binnen Suspense mag later komen, en de fallback is wat er ondertussen getoond wordt. De combinatie heet partial prerendering: de statische delen van een pagina worden al tijdens de build gemaakt, en alleen de dynamische gaten worden bij het request ingevuld en gestreamd. Dat is precies het model dat Next.js nu als standaard aanbeveelt, zie trend twee.
