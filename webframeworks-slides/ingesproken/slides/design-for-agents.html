Wat maakt een framework agent-vriendelijk?

  • Expliciet boven magie: geen verborgen caching, geen zone.js; het gedrag staat in de code
  • Types overal: de compiler vangt fouten op nog voor de app draait; type-safe routes
  • Sterke conventies: file-based routing, vaste projectstructuur; minder keuzes, minder fouten
  • Webstandaarden: Request, Response, FormData; kennis die niet veroudert (Remix 3)
  • Fouten met oplossing: gestructureerd, in de terminal, met een link naar uitleg
  • Snelle feedbacklus: Rust-tooling, snelle tests; een agent bouwt tientallen keren per taak

Wat goed is voor agents, is ook goed voor mensen.

Als we alles uit deze trend samenvatten: wat maakt een framework agent-vriendelijk? Zes principes komen steeds terug. Eén: expliciet boven magie. De impliciete caching in oudere versies van Next.js en zone.js in Angular waren al lastig voor mensen, maar voor agents nog meer, want het gedrag staat nergens in de code. Beide zijn intussen vervangen door expliciete alternatieven: ‘use cache’ en signals. Twee: types overal. TypeScript werkt als een vangnet: de compiler meldt meteen dat een agent iets fout deed, nog voor de app draait. Frameworks als TanStack Start gaan heel ver met type-safe routes en server-functies. Drie: sterke conventies, zoals file-based routing, waarbij de mappenstructuur bepaalt welke URL welke pagina toont. Hoe minder vrijheid in de structuur, hoe minder een agent kan fout doen, en hoe sneller hij een bestaand project begrijpt. Vier: webstandaarden. Request, Response, FormData en fetch veranderen niet elk kwartaal, en staan correct in de trainingsdata van elk model. Dat is precies het argument van het Remix-team: hun framework werkt goed met agents omdat het op webstandaarden bouwt, type-safe is en state in gewone JavaScript houdt. Vijf: foutmeldingen die meteen een oplossing aanreiken, in de terminal, waar een agent ze leest. Zes: een snelle feedbacklus. Een agent bouwt en test tientallen keren per taak; daarom is de investering in Rust-tooling zo belangrijk. En het mooiste: al deze principes maken een framework ook beter voor mensen. Developer experience en agent experience versterken elkaar.
