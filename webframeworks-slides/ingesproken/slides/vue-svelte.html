Ook Vue en Svelte laten de virtual DOM achter zich. Vue gebruikte tot nu toe een virtual DOM, net als React, maar met refs als reactieve waarden. Refs zijn in feite signals. Vue werkt al een tijd aan Vapor Mode: een nieuwe manier van compileren waarbij een Vue-template niet meer naar een virtuele boom wordt omgezet, maar rechtstreeks naar DOM-operaties die gekoppeld zijn aan de refs. Precies wat we bij het kernbegrip compilers zagen. Het resultaat: minder geheugengebruik, kleinere bundles en snellere updates. Het grote voordeel is dat je het per component kan aanzetten, met één woord in de script-tag. Je kan dus geleidelijk migreren. Let wel: eind september 2026 zat Vue 3.6 nog in release candidate. Het is dus nog niet officieel stabiel. Svelte was altijd al een compiler-framework. Sinds Svelte 5 gebruik je runes: dollar state voor een reactieve waarde, dollar derived voor een afgeleide waarde. Dat zijn signals, met een syntax die de Svelte-compiler herkent. De nieuwigheid in 2026 zit in SvelteKit 3, dat sinds augustus in release candidate zit: remote functions. Je definieert een functie in een apart bestand die op de server draait, bijvoorbeeld om de database te lezen, en je roept die vanuit je component aan alsof het een gewone lokale functie is. SvelteKit zorgt voor het HTTP-request erachter, en de types blijven kloppen tussen server en client. Dat principe heet RPC, remote procedure call: een functie aanroepen die op een andere machine draait. React heeft hetzelfde idee met Server Actions, en dat begrip komt terug bij trend drie.
