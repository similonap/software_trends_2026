Deze tabel zet de mechanismen naast elkaar. Het Next.js-team vatte de noden van een agent samen in drie woorden: kennis, zichtbaarheid en verificatie. Voor kennis zijn er AGENTS.md en llms.txt. AGENTS.md wordt altijd bij de start geladen en bevat de projectregels plus een verwijzing naar de juiste documentatie. llms.txt gebruikt een agent wanneer hij iets moet opzoeken. Voor workflows zijn er skills, die enkel geladen worden wanneer de taak erbij past. Voor zichtbaarheid is er MCP. Een agent kan via een tool-aanroep vragen welke fouten er in de browser zijn, welke routes bestaan of of een route compileert. En voor verificatie is er agent-browser: een tool waarmee een agent zelf een echte browser bestuurt, de console leest, netwerkverkeer bekijkt en zelfs de React-componentenboom inspecteert. Zo kan de agent controleren of zijn wijziging echt werkt, in plaats van te hopen dat ze werkt. Een leerrijk detail: Next.js bouwde eerst een eigen chat-agent in de browser, Vector genaamd. Die werd geschrapt, omdat developers toch al Cursor of Claude Code gebruikten voor al hun projecten. De les die het team trok: bouw geen eigen agent, maar maak je framework zichtbaar en begrijpbaar voor de agents die developers al gebruiken. Je ziet ook dat de mechanismen elkaar aanvullen: zowel Next.js als Angular maakten hun MCP-server in 2026 kleiner, omdat kennis beter via docs en skills loopt en MCP vooral dient voor live informatie.
