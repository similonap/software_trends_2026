Een concreet voorbeeld van hoe ver dit gaat: foutmeldingen. Links zie je de output die je in Next.js 16.3 in de terminal krijgt wanneer een route ongecachete data ophaalt zonder Suspense. Merk op hoe gestructureerd dat is: een duidelijke beschrijving, drie gelabelde oplossingen, stream, cache of block, en een link naar een documentatiepagina. Waarom staat dat ook in de terminal en niet alleen in de browser? Omdat een agent de terminal leest, niet je browser. Ook next build en CI-logs geven dezelfde structuur. In de browser-overlay staat bij die fout een knop ‘Copy prompt’. Je kiest een oplossing en krijgt een volledige prompt die je in je agent plakt, met stappen als: lees eerst deze documentatiepagina, pas het canonieke patroon toe, en verifieer daarna in een echte browser dat de pagina nog werkt. Die foutpagina's zijn bewust geschreven voor agents, met een vaste structuur: patronen, trade-offs tegenover de andere oplossingen, en valkuilen die een agent bij een eerste poging waarschijnlijk mist. Next.js 16.4, van begin oktober 2026, gaat nog verder. Met next upgrade --agent krijgt je agent de juiste migratiegidsen, codemods en verificatiestappen om je app naar de nieuwste versie te brengen. Er is een optie die je agent herinnert wanneer er een security-upgrade beschikbaar is. En er is agent feedback: de agent noteert tijdens het werk waar hij vastliep op onduidelijke documentatie of framework-fouten, en stelt bugrapporten op voor het Next.js-team. Niets wordt verstuurd zonder dat jij het nakijkt. Interessant is dat dit ook voor mensen beter is: duidelijke fouten met concrete oplossingen helpen iedereen.
