Regel 1: ander type

div én Counter worden vernietigd en opnieuw gemaakt. Counter verliest zijn state: terug naar 0!

Gevolg voor jou: wissel het type van een wrapper niet afhankelijk van state (bv. div als iets dicht is, section als het open is). Alles erin verliest dan zijn state.

Twee concrete voorbeelden maken de regels duidelijk. Bovenaan: in de vorige render was er een div met className card, met daarin een Counter-component. In de nieuwe render is de className card open geworden, bijvoorbeeld omdat de gebruiker op de kaart klikte. React begint bovenaan: het type is in beide gevallen div, dus regel twee. React vergelijkt de attributen en ziet dat alleen className veranderd is. Dat is de enige DOM-aanpassing. Daarna gaat React naar de kinderen: op dezelfde positie staat in beide bomen een Counter. Zelfde type, dus de Counter-instantie blijft bestaan, en zijn state, bijvoorbeeld de waarde 7, blijft bewaard. Onderaan: dezelfde vorige render, maar in de nieuwe render is de div een section geworden, met dezelfde className en dezelfde Counter erin. Voor een mens lijkt dat een kleine wijziging. Maar voor React geldt regel één: ander type. React probeert niets te hergebruiken. De oude div wordt uit de DOM verwijderd, inclusief alles erin, en een nieuwe section met een nieuwe Counter wordt gemaakt. De Counter begint dus weer bij nul. De gebruiker verliest zijn state, terwijl er inhoudelijk nauwelijks iets veranderde. Daar volgt een praktische les uit: verander het type van een wrapper-element niet afhankelijk van state, bijvoorbeeld een div wanneer iets gesloten is en een section wanneer het open is. Dan verlies je de state van alles erin. Er is nog een tweede valkuil met precies dezelfde oorzaak, maar die zie je veel moeilijker in de code. Die bekijken we op de volgende slide.
