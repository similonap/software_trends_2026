Client side rendering vs server side rendering

Client side rendering (CSR)

  1. Server stuurt een bijna lege HTML en een JS-bundle
  2. Browser downloadt en voert de JavaScript uit
  3. JavaScript haalt data op via een API (fetch)
  4. JavaScript bouwt de DOM op

Voordelen: rijke interactie, statische hosting, server enkel als API

Nadelen: trage eerste weergave, SEO moeilijker, veel JavaScript

Ook: SPA (single page application)

Server side rendering (SSR)

  1. Server haalt de data op (bv. uit de database)
  2. Server rendert de volledige HTML per request
  3. Browser toont meteen de inhoud
  4. JavaScript laadt en maakt de pagina interactief (hydration)

Voordelen: snelle eerste weergave, goed voor SEO

Nadelen: server nodig voor elk request, hydration kost tijd

Het eerste kernbegrip: waar wordt de HTML van een pagina gemaakt? Er zijn twee basismodellen. Client side rendering, afgekort CSR. De server stuurt een bijna lege HTML-pagina, met eigenlijk alleen een lege div en een verwijzing naar een groot JavaScript-bestand. De browser downloadt die JavaScript en voert ze uit. Die code haalt de data op via een API, bijvoorbeeld met fetch naar een REST-endpoint, en bouwt dan zelf de DOM op. Dit noemen we ook een single page application of SPA: er is maar één HTML-pagina, en navigeren gebeurt volledig in JavaScript. Voordelen: na het laden voelt alles heel snel en interactief, en je kan de frontend als statische bestanden hosten, met de server enkel als API. Nadelen: de gebruiker ziet eerst een wit scherm of een spinner tot alle JavaScript geladen is, zoekmachines en social media-previews zien soms een lege pagina, en je stuurt veel JavaScript naar het toestel van de gebruiker. Server side rendering, afgekort SSR. Bij elk request haalt de server de data op, rendert de componenten naar volledige HTML en stuurt die naar de browser. De gebruiker ziet meteen inhoud. Daarna wordt de JavaScript geladen om de pagina interactief te maken; dat proces heet hydration en bespreken we op de volgende slide. Voordelen: snelle eerste weergave en goed voor SEO. Nadelen: je hebt een server nodig die bij elk request werk doet, wat kost, en de hydration-stap kost extra tijd. Een typisch examenvoorbeeld: een admin-dashboard achter een login heeft geen SEO nodig en veel interactie: CSR volstaat. Een webshop wil gevonden worden door Google: SSR of een variant ervan.
