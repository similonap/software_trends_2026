Hydration

Hydration is het proces waarbij de browser JavaScript uitvoert om server-gerenderde, statische HTML interactief te maken: de componenten draaien opnieuw en koppelen event handlers aan de bestaande DOM.

1. HTML aangekomen

Zichtbaar, maar knoppen doen nog niets

2. JavaScript laden

Code van alle componenten downloaden en uitvoeren

3. Interactief

Event handlers gekoppeld, state actief

  • Nadeel: dubbel werk (renderen op de server én in de browser) en alle componentcode moet toch naar de browser
  • Oplossingen: partial/incremental hydration (Angular), islands (Astro), Server Components (React)

Hydration is een van de belangrijkste begrippen om moderne frameworks te begrijpen. Bij server side rendering krijgt de browser kant-en-klare HTML. Die ziet er volledig uit, maar het is gewoon tekst: een knop in die HTML heeft nog geen click handler, een formulier heeft nog geen validatie. Om de pagina interactief te maken, moet het framework in de browser opnieuw dezelfde componenten uitvoeren. Het bouwt intern de componentenboom op, vergelijkt die met de HTML die er al staat, en koppelt de event handlers en de state aan de bestaande DOM-elementen. Dat heet hydration: de droge HTML wordt bevochtigd met JavaScript, zoals je een gedroogde spons onder water houdt. Kijk naar de drie fases. Eerst is de HTML zichtbaar, maar niet interactief. Klik je op dat moment op een knop, dan gebeurt er niets. Dan wordt de JavaScript geladen en uitgevoerd. Pas daarna is de pagina interactief. Het nadeel is duidelijk: je doet het werk dubbel. De server rendert de componenten, en de browser voert diezelfde componenten nog eens uit. En de code van alle componenten moet naar de browser, ook van stukken die nooit interactief zijn, zoals een footer of een artikeltekst. Daarom zijn er verschillende oplossingen ontstaan. Partial of incremental hydration: alleen bepaalde delen hydrateren, of pas wanneer ze nodig zijn, bijvoorbeeld wanneer ze in beeld komen. Angular doet dat sinds versie 22 standaard. Islands: alleen de interactieve eilandjes op een verder statische pagina krijgen JavaScript, zoals bij Astro. En React Server Components: componenten die nooit naar de browser gaan en dus ook niet gehydrateerd moeten worden.
