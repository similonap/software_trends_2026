React.memo en referentiële gelijkheid

React.memo

const TodoList = memo(({ todos }) => {
  /* ... */
});

Vergelijkt de oude en nieuwe props één voor één (shallow, met Object.is). Zijn ze allemaal gelijk, dan wordt de render overgeslagen, ook als de parent rendert.

Kost zelf ook iets: de vergelijking gebeurt bij elke render van de parent.

Het addertje: referenties

1 === 1             // true
'a' === 'a'         // true
{} === {}           // false
(() => 1) === (() => 1) // false

<TodoList todos={todos}

Een nieuw object of een nieuwe functie is een nieuwe referentie. memo ziet dus ‘andere props’ en rendert toch.

Kernbegrip

De eerste oplossing voor de re-render cascade is React.memo. Links zie je hoe het werkt: je wikkelt een component in memo. Wanneer de parent opnieuw rendert, vergelijkt React eerst de oude en de nieuwe props van dat component, één voor één. Dat heet een shallow comparison, een oppervlakkige vergelijking: React kijkt niet in objecten, maar vergelijkt elke prop met Object.is, wat ongeveer overeenkomt met drie gelijktekens. Zijn alle props gelijk, dan slaat React de render van dat component over, en dus ook van al zijn kinderen. In ons voorbeeld: als TodoList in memo zit, en todos is dezelfde array, dan renderen TodoList en de vijfhonderd items niet meer mee als de teller verandert. Let wel: die vergelijking kost zelf ook iets, bij elke render van de parent. Memo overal gebruiken is dus niet gratis. Rechts zie je het addertje onder het gras: referentiële gelijkheid. Primitieve waarden zoals getallen en strings worden op waarde vergeleken: één is gelijk aan één. Maar objecten, arrays en functies worden in JavaScript vergeleken op referentie, op hun adres in het geheugen. Twee lege objecten die er exact hetzelfde uitzien, zijn niet gelijk, omdat het twee verschillende objecten zijn. En twee identieke arrow functions zijn ook niet gelijk. Waarom is dat een probleem? Kijk naar het tweede codeblok. App geeft aan TodoList niet alleen todos mee, maar ook een functie onAdd, geschreven als arrow function in de JSX. Elke keer dat App rendert, wordt die regel opnieuw uitgevoerd, en dus wordt er een nieuwe functie gemaakt. Een nieuwe referentie. memo vergelijkt de props, ziet dat onAdd niet gelijk is aan de vorige onAdd, en besluit dat de props veranderd zijn. TodoList rendert dus toch opnieuw. memo doet niets meer. Hetzelfde gebeurt als je een object of array rechtstreeks in de JSX aanmaakt, zoals style={{ color: 'red' }}. Om memo te laten werken, moet je ervoor zorgen dat objecten en functies tussen renders dezelfde referentie houden. Daarvoor bestaan useMemo en useCallback.
