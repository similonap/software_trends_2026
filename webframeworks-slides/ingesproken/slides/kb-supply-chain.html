Er is nog een tweede aanvalsoppervlak, en dat is niet je eigen code, maar alle code waarop je steunt: je dependencies. Een dependency is een package dat je project nodig heeft, bijvoorbeeld React of zod. Maar die packages hebben zelf ook dependencies, en die weer andere. Een dependency van een dependency noemen we een transitieve dependency. Een gloednieuw Next.js-project installeert al honderden packages, geschreven door honderden verschillende mensen. Je vertrouwt ze allemaal. Een supply chain attack is een aanval via zo'n onderdeel. In plaats van jouw goed beveiligde applicatie aan te vallen, valt een aanvaller een klein package aan dat duizenden projecten gebruiken. Een paar begrippen die daarbij horen. Semantic versioning, of semver: versienummers in de vorm major, minor, patch. Een major-versie mag dingen breken, een minor voegt features toe, een patch lost bugs op. In package.json betekent het dakje voor een versie dat npm automatisch elke nieuwere 1.x-versie mag installeren. Handig voor updates, maar als iemand een kwaadaardige 1.4.3 publiceert, krijg je die automatisch. Daarom is er de lockfile, package-lock.json: die legt de exacte versie van elk package vast, ook van de transitieve. Met npm ci installeer je exact wat in de lockfile staat. Install-scripts, zoals postinstall, zijn stukjes code die automatisch draaien wanneer je een package installeert. Ideaal voor aanvallers. Typosquatting: een malafide package met een naam die bijna gelijk is aan een bekend package, in de hoop dat iemand een typfout maakt. En een nieuwe variant uit het AI-tijdperk: slopsquatting. AI-modellen verzinnen soms package-namen die niet bestaan. Aanvallers registreren precies die namen, zodat een agent die het verzonnen package installeert, malware binnenhaalt.
