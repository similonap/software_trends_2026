Library vs framework: wie roept wie aan?

Library: jij roept de code aan

Jouw code

date-fns

import { format } from 'date-fns';

knop.addEventListener('click', () => {
  label.textContent =
    format(new Date(), 'dd/MM/yyyy');
});

Jij beslist wanneer format() loopt, en jij past de DOM aan.

Framework-gedrag: de code roept jou aan

React

Jouw component

function Klok() {
  const [datum, setDatum] = useState('');
  const toon = () =>
    setDatum(format(new Date(), 'dd/MM/yyyy'));
  return <button onClick={toon}>{datum}</button>;
}

createRoot(app).render(<Klok />);

Jij roept Klok() nooit zelf aan en raakt de DOM niet aan: React beslist wanneer het rendert.

Inversion of control (Hollywood-principe): don’t call us, we’ll call you. Je geeft de controle over de flow van je programma af.

Kernbegrip

4

Laten we beginnen bij de basis: wat is het verschil tussen een library en een framework? Het korte antwoord, en dat is ook de definitie die je moet kennen: een library roep jij aan, een framework roept jou aan. Links zie je een library. We gebruiken date-fns, een library om datums te formatteren, in gewone JavaScript. Jij registreert een click-handler op een knop. Wanneer de gebruiker klikt, roep jij de functie format uit de library aan, en jij zet het resultaat zelf in de DOM met textContent. Jij bepaalt de structuur van je programma en het moment waarop de library iets doet. Een library is een gereedschapskist: ze doet niets tot jij ze aanroept. Rechts zie je hetzelfde in React. Je schrijft een functie Klok die beschrijft wat er op het scherm moet staan. Maar kijk goed: nergens in je code staat Klok(). Jij geeft het component één keer aan React met createRoot en render, en vanaf dan beslist React wanneer Klok uitgevoerd wordt: bij het opstarten, en opnieuw telkens wanneer setDatum de state verandert. Ook de DOM pas je niet zelf aan. React vergelijkt het nieuwe resultaat met het vorige en voert zelf de nodige DOM-wijzigingen uit. Hoe dat precies werkt, zien we straks bij de virtual DOM en reconciliation. Dat omkeren van de controle heet inversion of control, of het Hollywood-principe: don't call us, we'll call you. Jij levert stukjes code aan volgens de regels van het framework, en het framework beslist wanneer ze lopen. Merk ook op dat date-fns rechts gewoon een library blijft: binnen je React-component roep jij format nog altijd zelf aan. Volgens die definitie doet React dus wel degelijk aan inversion of control, en gedraagt het zich op dat vlak als een framework. Toch noemt React zichzelf officieel een library.
