Wat genereert de React Compiler?

Jij schrijft

function TodoList({ todos, tab }) {
  const zichtbaar =
    filter(todos, tab);
  return <List items={zichtbaar} />;
}

  • _c(5) maakt per component-instantie een cache-array met 5 slots
  • Per waarde: slots voor de inputs en het resultaat
  • Inputs gelijk? Dan komt het resultaat uit de cache
  • Zelfde JSX-object: React slaat die deelboom over

De compiler maakt ervan (vereenvoudigd)

function TodoList({ todos, tab }) {
  const $ = _c(5);
  let zichtbaar;
  if ($[0] !== todos || $[1] !== tab) {
    zichtbaar = filter(todos, tab);
    $[0] = todos; $[1] = tab; $[2] = zichtbaar;
  } else zichtbaar = $[2];
  let el;
  if ($[3] !== zichtbaar) {
    el = <List items={zichtbaar} />;
    $[3] = zichtbaar; $[4] = el;
  } else el = $[4];
  return el;
}

Hoe doet de compiler dat precies? Het is leerrijk om naar de gegenereerde code te kijken. Rechts zie je een vereenvoudigde versie van wat de compiler van het component links maakt. Bovenaan staat const dollar is underscore c van vijf. Die functie komt uit react/compiler-runtime en maakt voor elke instantie van het component een cache-array met vijf vakjes, die bewaard blijft tussen renders. Intern gebruikt React daarvoor een hook die useMemoCache heet. Dan de berekening van zichtbaar. De compiler heeft geanalyseerd dat zichtbaar alleen afhangt van todos en tab. Hij genereert dus een if-test: is todos anders dan wat in vakje nul staat, of tab anders dan wat in vakje één staat? Dan voert hij de berekening uit en bewaart hij de inputs in vakje nul en één, en het resultaat in vakje twee. Zijn beide inputs gelijk, dan haalt hij het resultaat gewoon uit vakje twee. Dat is precies wat useMemo met de dependency array todos en tab zou doen, maar zonder dat jij de dependencies moet opschrijven: de compiler kan ze niet vergeten. Daarna de JSX. Ook het List-element wordt gememoïzeerd: alleen als zichtbaar veranderd is, wordt een nieuw JSX-object gemaakt. Anders wordt het oude object uit vakje vier teruggegeven. En dat is de truc die React.memo vervangt: als React bij reconciliation exact hetzelfde element-object tegenkomt als de vorige keer, weet het dat er niets veranderd is, en slaat het het renderen van List en alles eronder over. Merk op dat de compiler gewone if-statements genereert, geen hooks. Daarom kan hij ook memoïzeren na een vroege return of binnen een conditie, wat met useMemo niet mag. Een interessante vergelijking: de compiler doet in feite wat signals doen, namelijk bijhouden welke waarde van welke andere afhangt, maar dan tijdens de build in plaats van tijdens het uitvoeren. React behoudt zijn model van volledige re-renders, maar die re-renders worden zo goedkoop dat het verschil klein wordt.
