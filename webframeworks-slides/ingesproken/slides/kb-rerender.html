Waarom rendert een component opnieuw?

  1. Zijn eigen state verandert (setState)
  2. Zijn parent rendert opnieuw, ook als de props gelijk zijn
  3. Een context die het gebruikt verandert

  const [count, setCount] = useState(0);

  return <>
    <button onClick={() => setCount(count + 1)}>

Om te begrijpen wat de React Compiler oplost, moeten we eerst weten wanneer een React-component opnieuw rendert. Er zijn drie redenen. Eén: zijn eigen state verandert, via een set-functie zoals setCount. Twee: zijn parent rendert opnieuw. En dat is de belangrijke: standaard rendert React alle kinderen van een component opnieuw wanneer dat component rendert, ook als hun props exact hetzelfde zijn gebleven. Drie: een context waar het component van leest, verandert. Kijk naar de code rechts. App heeft twee stukken state: een teller count en een lijst todos. Het toont een knop met de teller, en een TodoList die de todos krijgt. Stel dat die lijst vijfhonderd items bevat, elk een eigen TodoItem-component. Wat gebeurt er als je op de knop klikt? setCount verandert de state van App, dus App rendert opnieuw: dat is reden één. De button toont een nieuw getal, prima. Maar dan reden twee: omdat App rendert, rendert ook TodoList opnieuw, ook al is todos exact dezelfde array als voorheen. En omdat TodoList rendert, renderen ook alle vijfhonderd TodoItems. Na reconciliation blijkt er in de lijst niets veranderd te zijn, dus er gebeuren nul DOM-aanpassingen. Maar React heeft wel vijfhonderd en één componentfuncties uitgevoerd en vijfhonderd en één virtuele deelbomen vergeleken, voor niets. Dat noemen we een re-render cascade: een update bovenaan de boom stroomt door naar alles eronder. In kleine apps merk je daar niets van. In grote apps, met zware componenten of lange lijsten, wordt de interface daardoor traag, bijvoorbeeld als je typt in een invoerveld en elke toetsaanslag de halve pagina laat herrenderen. Merk op dat dit het fundamentele verschil is met signals: daar zou alleen de tekstnode van de knop aangepast worden. React heeft daarom extra hulpmiddelen nodig om die onnodige renders over te slaan. Dat zijn React.memo, useMemo en useCallback.
