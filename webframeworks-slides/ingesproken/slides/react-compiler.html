Nu we weten wat memo, useMemo en useCallback doen en waarom ze lastig zijn, kunnen we de React Compiler begrijpen. Versie 1.0 kwam uit op 7 oktober 2025. De React Compiler is een build-tool, een plugin voor Babel en sinds kort ook beschikbaar in Turbopack, die tijdens de build elk component en elke custom hook analyseert. Hij bekijkt welke waarden van welke andere waarden afhangen, en voegt automatisch memoization toe. Je schrijft dus gewone code zoals rechts, en het resultaat gedraagt zich alsof je links overal correct memo, useMemo en useCallback gebruikt had. Welke hooks vervangt hij? Drie dingen. React.memo: de compiler memoïzeert de JSX die een component teruggeeft. Als de props van een kind niet veranderd zijn, krijgt React exact hetzelfde JSX-object terug en slaat het die deelboom over. useMemo: berekende waarden zoals visible worden onthouden zolang todos en tab gelijk blijven. useCallback: functies zoals onAdd krijgen een stabiele referentie zolang de variabelen die ze gebruiken niet veranderen. Hij kan bovendien meer dan handmatige memoization. Omdat hij geen hooks gebruikt maar code genereert, kan hij ook memoïzeren na een vroege return of binnen een if, wat met useMemo verboden is door de Rules of Hooks. En hij memoïzeert fijnmaziger: de officiële documentatie toont een voorbeeld waarbij een developer useCallback gebruikte, maar toch een nieuwe inline arrow function aan een kind meegaf, waardoor de memo van dat kind niets deed. De compiler doet dat wel correct. Wat vervangt hij niet? Hooks met een andere functie: useState voor state, useEffect voor side effects, useRef, useContext. Die blijf je gewoon gebruiken. En useMemo of useCallback mag je nog gebruiken als escape hatch, bijvoorbeeld om precies te bepalen wanneer een effect opnieuw draait. Het resultaat in de praktijk: in de Meta Quest Store werden laadtijden en navigaties tot twaalf procent sneller, en sommige interacties meer dan tweeënhalf keer sneller. De compiler werkt met React 17 en hoger, en is ingebouwd in Next.js, Vite-templates en Expo.
