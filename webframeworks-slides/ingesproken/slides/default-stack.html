Eerste punt: wie kiest vandaag eigenlijk het framework? Steeds vaker het taalmodel. Als je een AI zonder verdere context vraagt om een todo-app te bouwen, krijg je opvallend vaak dezelfde stack: React, met Next.js of Vite, Tailwind voor de styling en shadcn/ui voor de componenten. Bij v0 van Vercel, bij Lovable, bij Claude. Ik benadruk dat dit observaties zijn uit blogposts en de praktijk, geen grote wetenschappelijke studie, maar het patroon wordt breed herkend. Twee begrippen. Tailwind is een CSS-framework waarbij je niet zelf CSS-klassen schrijft, maar kleine utility-klassen in je HTML zet, zoals p-4 voor padding of text-center. De styling staat dus naast de markup, wat handig is voor een model dat alles in één bestand ziet. shadcn/ui is een componentcollectie die je niet als dependency installeert, maar waarvan je de broncode in je eigen project kopieert. Een agent kan die code dus gewoon lezen en aanpassen. Rechts zie je waarom dat een probleem kan worden: een vliegwiel, een zichzelf versterkende cirkel. Wat populair is, domineert de trainingsdata. Modellen genereren dus vooral die stack. Die gegenereerde code komt online terecht en wordt trainingsdata voor volgende modellen. Voor React is dat een enorm voordeel, en het verklaart mee waarom React dominant blijft ondanks de lagere tevredenheid. Voor Vue, Svelte, Angular en zeker voor nieuwe frameworks is het een drempel: ze moeten niet alleen developers overtuigen, maar ook in de modellen raken. Precies daarom investeren ze zwaar in AGENTS.md, skills en llms.txt. Als developer kan je je agent bijsturen: expliciete instructies, een AGENTS.md met je stack, voorbeeldcomponenten in je codebase en lint-regels.
