Serialisatie en deserialisatie

  • Serialiseren: een object uit het geheugen omzetten naar tekst of bytes, om te versturen of op te slaan
  • Deserialiseren: die tekst weer omzetten naar een object in het geheugen

const tekst = JSON.stringify({ id: 5, tags: ['a'] }); // '{"id":5,"tags":["a"]}'
const obj   = JSON.parse(tekst);

Waarom gevaarlijk?

JSON kent enkel data. Rijkere formaten kunnen ook verwijzingen, promises of modules reconstrueren. Stuurt een aanvaller slim gekozen input, dan kan de parser objecten maken of functies aanroepen die nooit bedoeld waren.

Flight-protocol

Het formaat van React voor de RSC-payload en de argumenten van Server Actions. Het ondersteunt veel meer dan JSON, en dus kan er ook meer foutlopen.

Serialisatie is een begrip dat je ook buiten webdevelopment tegenkomt. Serialiseren betekent een object in het geheugen omzetten naar een reeks tekens of bytes, zodat je het kan versturen over een netwerk of kan opslaan in een bestand. Deserialiseren is het omgekeerde: van die tekst weer een object maken. Het bekendste voorbeeld in JavaScript is JSON. JSON.stringify zet een object om naar een string, JSON.parse maakt er weer een object van. JSON is bewust beperkt: het kent alleen getallen, strings, booleans, null, arrays en objecten. Er zitten geen functies, klassen of verwijzingen in. Daardoor is JSON.parse relatief veilig: het ergste wat er kan gebeuren, is dat je onverwachte data krijgt. Maar sommige formaten kunnen veel meer. Ze kunnen verwijzingen tussen objecten bewaren, promises voorstellen die later ingevuld worden, of zelfs aangeven welke module of klasse er gebruikt moet worden. Dat is krachtig, maar gevaarlijk als de input van een aanvaller komt. Met slim geconstrueerde input kan een aanvaller de parser objecten laten maken of functies laten aanroepen die nooit bedoeld waren, en in het slechtste geval leidt dat tot remote code execution. Deserialisatie van onbetrouwbare data staat daarom al jaren in de OWASP-lijst van belangrijkste webkwetsbaarheden; bekende voorbeelden zijn Java-serialisatie en pickle in Python. React gebruikt voor Server Components en Server Actions een eigen formaat: het Flight-protocol. Daarmee stuurt de server de RSC-payload naar de browser, en stuurt de browser de argumenten van Server Actions naar de server. Flight ondersteunt veel meer dan JSON: promises, verwijzingen, streaming. En dus is er ook meer dat fout kan lopen. Dat is precies wat er in december 2025 gebeurde.
