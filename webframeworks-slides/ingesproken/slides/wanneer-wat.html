Hoe kies je dan? Deze tabel brengt alle rendering-begrippen samen in een beslissingshulp. Het is een vereenvoudiging, maar een goed vertrekpunt, ook voor examenvragen van het type: welke rendering-strategie kies je voor deze applicatie, en waarom? Content zoals een blog, documentatie of een portfolio verandert zelden en moet goed vindbaar zijn: static site generation, eventueel met islands voor de paar interactieve stukjes. Astro is daar ideaal voor. Een webshop of marketingsite moet snel laden en gevonden worden door zoekmachines, maar heeft ook persoonlijke delen, zoals een winkelmandje of aanbevelingen. Dan wil je een statische shell met gestreamde dynamische delen, precies waar Cache Components voor ontworpen is. Een dashboard, admin-omgeving of chat-applicatie zit achter een login. SEO is dus irrelevant, interactiviteit is alles. Een klassieke SPA met client side rendering is vaak eenvoudiger, goedkoper en sneller. Voor apps met veel formulieren, zoals een overheidsformulier of een inschrijvingssysteem, is SSR met progressive enhancement sterk, omdat het ook werkt op trage toestellen of als JavaScript faalt. Een belangrijke vuistregel: server side rendering is geen doel op zich. Elke stap richting de server betekent meer serverkosten, en ook meer aanvalsoppervlak: meer code die publiek bereikbaar is op een server. Dat brengt ons bij trend drie.
