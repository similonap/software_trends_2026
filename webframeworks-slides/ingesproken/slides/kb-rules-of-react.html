De Rules of React

  1. Componenten zijn puur: zelfde props en state geven dezelfde JSX. Geen side effects tijdens het renderen (geen fetch, geen globale variabele aanpassen).
  2. Immutability: props en state nooit aanpassen, altijd een nieuwe kopie maken.
  3. Rules of Hooks: hooks enkel bovenaan een component of custom hook. Niet in een if, een lus of na een early return.

✗ todos.push(t);
  setTodos(todos);
✓ setTodos([...todos, t]);

Breek je een regel? Dan slaat de compiler dat component over (bail-out): het werkt nog, maar zonder optimalisatie. eslint-plugin-react-hooks waarschuwt al tijdens het schrijven. Uitschakelen per component kan met 'use no memo'.

De compiler kan alleen veilig memoïzeren als je code zich aan een aantal regels houdt: de Rules of React. Die regels gelden eigenlijk altijd in React, maar met de compiler worden ze echt belangrijk. Regel één: componenten en hooks zijn puur. Een pure functie geeft voor dezelfde input altijd dezelfde output, en heeft geen side effects. Voor een component betekent dat: dezelfde props en state leveren dezelfde JSX op. Tijdens het renderen mag je dus geen data versturen, geen globale variabelen aanpassen en geen willekeurige waarden gebruiken die de output veranderen. Side effects horen in event handlers of in useEffect. Waarom is dat belangrijk? Als de compiler een resultaat uit de cache haalt, wordt je componentcode niet uitgevoerd. Had die code een side effect, dan zou die plots niet meer gebeuren. Regel twee: immutability, onveranderlijkheid. Je past props en state nooit rechtstreeks aan; je maakt altijd een nieuwe kopie. Kijk naar het voorbeeld. Met todos.push voeg je een item toe aan de bestaande array, en geef je diezelfde array terug aan setTodos. Maar het is nog altijd dezelfde referentie. React en de compiler vergelijken met triple is gelijk, zien dezelfde referentie, en besluiten dat er niets veranderd is. Je nieuwe item verschijnt niet op het scherm. De juiste manier is met de spread-operator een nieuwe array maken met alle oude items plus het nieuwe. Dat is een nieuwe referentie, dus React ziet de wijziging. Regel drie: de Rules of Hooks. Hooks roep je alleen bovenaan een component of custom hook aan, nooit in een if-statement, een lus of na een vroege return. React herkent hooks namelijk aan hun volgorde: de eerste useState is altijd de eerste, de tweede altijd de tweede. Als een hook soms wel en soms niet wordt uitgevoerd, raakt die volgorde in de war. Wat gebeurt er als je een regel breekt? De compiler detecteert het en slaat dat ene component over. Dat heet een bail-out. Het component werkt gewoon, maar zonder automatische optimalisatie. Sinds versie 1.0 zitten de controles van de compiler in eslint-plugin-react-hooks, zodat je editor al tijdens het schrijven waarschuwt. En wil je de compiler voor een bepaald component uitschakelen, dan zet je de directive ‘use no memo’ bovenaan de functie.
