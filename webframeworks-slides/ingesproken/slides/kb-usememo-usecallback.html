useMemo en useCallback

useMemo onthoudt een waarde

const zichtbaar = useMemo(
  () => filter(todos, tab), // berekening
  [todos, tab]             // dependencies
);

Herberekent enkel als todos of tab veranderd is; anders krijg je dezelfde array terug (dezelfde referentie). Voor dure berekeningen of stabiele objecten.

useCallback onthoudt een functie

const onAdd = useCallback(
  () => add(tekst),
  [tekst]
);

Geeft dezelfde functie terug zolang tekst gelijk blijft, zodat een memo-kind ‘gelijke props’ ziet. Eigenlijk is het useMemo(() => fn, deps).

  • Nadelen:
  • Dependency vergeten: verouderde waarde (stale closure) en subtiele bugs
  • Overal gebruikt: extra geheugen en vergelijkingen, minder leesbare code
  • Rules of Hooks: niet in een if of na een early return, dus niet overal bruikbaar

De twee hooks die het referentieprobleem oplossen, zijn useMemo en useCallback. useMemo onthoudt een berekende waarde tussen renders. Je geeft twee dingen mee. Eerst een functie die de berekening doet, hier het filteren van de todos volgens de actieve tab. Daarna een array van dependencies: de waarden waar de berekening van afhangt. Bij de eerste render voert React de berekening uit en bewaart het resultaat. Bij elke volgende render vergelijkt React de dependencies met die van de vorige keer. Zijn todos en tab niet veranderd, dan geeft React het bewaarde resultaat terug, exact dezelfde array, met dezelfde referentie. Is een dependency veranderd, dan wordt de berekening opnieuw gedaan. useMemo dient dus voor twee dingen: dure berekeningen niet onnodig herhalen, en objecten of arrays een stabiele referentie geven, zodat memo-kinderen niet onnodig renderen. useCallback doet hetzelfde, maar voor functies. Het geeft dezelfde functie terug zolang de dependencies, hier tekst, niet veranderen. Zo krijgt een kind in memo bij elke render dezelfde onAdd-referentie en kan het zijn render overslaan. useCallback is eigenlijk een afkorting voor useMemo met een functie die een functie teruggeeft. Samen met React.memo vormen deze drie het klassieke gereedschap voor performance in React. Maar ze hebben duidelijke nadelen, die je onderaan ziet. Eén: vergeet je een dependency, dan gebruikt de functie of waarde een verouderde versie van een variabele. Dat heet een stale closure: de functie heeft de waarde van tekst onthouden van een vorige render. Dat geeft subtiele, moeilijk te vinden bugs. Twee: veel developers gaan alles memoïzeren voor de zekerheid. Dat kost extra geheugen en vergelijkingen, en maakt de code moeilijker leesbaar. Andere developers vergeten het net op de plek waar het nodig is. Drie: hooks moeten volgens de Rules of Hooks altijd in dezelfde volgorde aangeroepen worden, dus niet in een if-statement of na een vroege return. Je kan dus niet overal memoïzeren waar je zou willen. Precies deze drie problemen lost de React Compiler op.
