Begrippenlijst (1/3): rendering en reactiviteit

Inversion of control: het framework roept jouw code aan, niet omgekeerd

Meta-framework: bouwt op een UI-framework en voegt routing, SSR, data en build toe

Build tool / bundler: transpileert, bundelt, tree-shaket en minificeert code

CSR: HTML wordt in de browser opgebouwd door JavaScript

SSR: de server rendert de volledige HTML per request

Hydration: server-HTML interactief maken door componenten opnieuw in de browser te draaien

SSG: HTML wordt één keer gemaakt tijdens de build

Streaming: HTML in stukken over één response; shell eerst, trage delen later

Server Component: draait enkel op de server, de code gaat niet naar de browser

Client Component: 'use client'; voorgerenderd en gehydrateerd, kan state en events

CDN: netwerk van servers wereldwijd dat kopieën dicht bij de gebruiker bewaart

Signal: reactieve waarde die zijn afhankelijken kent en enkel die bijwerkt

Framework-compiler: zet componentcode tijdens de build om naar geoptimaliseerde JS

Partial prerendering: statische shell bij de build, dynamische delen streamen bij het request

Zoneless / OnPush: Angular zonder zone.js / component enkel controleren als het nodig is

Deze slide en de volgende vatten de belangrijkste begrippen uit de les samen, elk met een definitie in één zin. Ze zijn bedoeld als studiehulp voor het examen; in de les kan je ze snel overlopen of overslaan. Op deze eerste slide staan de begrippen over rendering en reactiviteit. Een goede oefening: probeer bij elk begrip niet alleen de definitie te geven, maar ook een voordeel, een nadeel en een voorbeeld van een framework dat het gebruikt. Bijvoorbeeld bij hydration: het voordeel is dat een server-gerenderde pagina interactief wordt; het nadeel is dat het werk dubbel gebeurt; en oplossingen zijn islands in Astro, incremental hydration in Angular en Server Components in React.
