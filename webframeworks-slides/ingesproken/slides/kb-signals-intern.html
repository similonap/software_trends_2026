Hoe werkt een signal vanbinnen?

let actief = null; // het effect dat nu draait
function signal(waarde) {
  const abonnees = new Set();
  const lees = () => {
    if (actief) abonnees.add(actief);
    return waarde;
  };
  lees.set = (nieuw) => {
    waarde = nieuw;
    abonnees.forEach((fn) => fn());
  };
  return lees;
}
function effect(fn) {
  actief = fn; fn(); actief = null;
}

const count = signal(0);
effect(() =>
  el.textContent = count());
count.set(5);

  1. effect zet zichzelf als actief en draait
  2. Het leest count(), dus count registreert het effect als abonnee
  3. count.set(5): enkel de abonnees draaien opnieuw, één tekstnode wordt aangepast

Geen boom, geen diff. Echte frameworks voegen nog computed, batching en opruimen toe.

Kernbegrip

23

Signals lijken misschien magisch, maar het basisprincipe past in vijftien regels JavaScript. Deze vereenvoudigde implementatie helpt om te begrijpen wat dependency tracking betekent. Bovenaan staat een globale variabele actief. Die houdt bij welk effect op dit moment aan het draaien is. De functie signal maakt een reactieve waarde. Ze houdt een Set bij met abonnees: de effecten die van deze waarde afhangen. Ze geeft een functie lees terug. Wanneer iemand de waarde leest, controleert lees of er op dat moment een effect actief is. Zo ja, dan wordt dat effect als abonnee toegevoegd. Daarnaast is er lees.set: die past de waarde aan en voert alle abonnees opnieuw uit. De functie effect zet de meegegeven functie als actief, voert ze één keer uit, en zet actief daarna weer op null. Kijk nu naar het gebruik rechtsboven. We maken een signal count met waarde nul. Dan maken we een effect dat de tekst van een element gelijkstelt aan count(). Stap één: effect zet de functie als actief en voert ze uit. Stap twee: tijdens het uitvoeren wordt count() gelezen. Op dat moment is het effect actief, dus count voegt het effect toe aan zijn abonnees. Niemand heeft expliciet gezegd dat dit effect van count afhangt: dat werd automatisch ontdekt door het lezen. Dat is dependency tracking. Stap drie: we roepen count.set(5) aan. De waarde wordt vijf en alle abonnees van count worden opnieuw uitgevoerd. Precies één effect, dat precies één tekstnode aanpast. Vergelijk dat met de virtual DOM: daar wordt de volledige componentfunctie opnieuw uitgevoerd, wordt een nieuwe boom gemaakt en vergeleken. Hier is er geen boom en geen diff: de signal weet op voorhand exact wat er moet gebeuren. Echte implementaties, zoals in Angular, Solid of Preact, voegen nog veel toe: computed-waarden die gecachet worden, batching zodat meerdere wijzigingen tot één update leiden, het opruimen van oude abonnementen, en het vermijden van dubbele uitvoeringen. Maar het kernidee is exact dit.
