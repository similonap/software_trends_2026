Valkuil: een component binnen een component

Fout: Veld staat binnen Formulier

function Formulier() {
  const [naam, setNaam] = useState('');
  // nieuwe functie bij elke render
  function Veld() {
    return <input value={naam}
      onChange={e => setNaam(e.target.value)} />;
  }
  return <Veld />;
}

Juist: Veld staat erbuiten, data via props

function Veld({ naam, setNaam }) {
  return <input value={naam}
    onChange={e => setNaam(e.target.value)} />;
}

function Formulier() {
  const [naam, setNaam] = useState('');
  return <Veld naam={naam} setNaam={setNaam} />;
}

  1. Je typt een letter: setNaam, dus Formulier rendert opnieuw.
  2. Daarbij wordt function Veld opnieuw uitgevoerd: er ontstaat een nieuwe functie.
  3. Het type van <Veld /> is die functie zelf. React vergelijkt types met ===: oude Veld !== nieuwe Veld.
  4. Regel 1, ander type: het oude input wordt vernietigd en een nieuw gemaakt. Focus en eigen state zijn weg.

Kernbegrip

20

Dit is een klassieke beginnersfout, en ze volgt rechtstreeks uit regel één van het reconciliation-algoritme. Om ze te begrijpen moet je eerst weten wat het type van een element precies is. Bij een gewone HTML-tag zoals input is het type de string 'input'. Bij een component zoals Veld is het type niet de naam Veld, maar het functie-object Veld zelf. React vergelijkt types met ===, dus op identiteit: twee functies zijn enkel gelijk als het exact hetzelfde object in het geheugen is, ook al hebben ze dezelfde naam en dezelfde code. Links zie je de fout. Het component Veld staat binnen het component Formulier. Volg wat er gebeurt als de gebruiker een letter typt. Het onChange-event roept setNaam aan. De state van Formulier verandert, dus Formulier rendert opnieuw: de functie Formulier wordt opnieuw uitgevoerd. Daarbij wordt ook de regel function Veld opnieuw uitgevoerd, en die maakt een nieuw functie-object. In de vorige virtuele boom stond een element met als type de oude Veld-functie, in de nieuwe boom een element met als type de nieuwe Veld-functie. Voor ons is dat hetzelfde, maar oude Veld === nieuwe Veld is false. Voor React is het dus een ander type, en dan geldt regel één: de volledige deelboom wordt verwijderd en opnieuw opgebouwd. Het oude input-element verdwijnt uit de DOM en er komt een nieuw in de plaats. Het gevolg: na elke letter verliest het invoerveld zijn focus, want het element waarin je typte bestaat niet meer. Had Veld een eigen useState, dan zou die state bij elke letter terug naar de beginwaarde gaan. Het is dus exact hetzelfde als de div die een section werd op de vorige slide, alleen zie je het verschil in type niet in de code. Rechts zie je de oplossing. Definieer Veld buiten Formulier, op het hoogste niveau van het bestand. Dan wordt de functie maar één keer gemaakt, wanneer het bestand geladen wordt, en is het type bij elke render hetzelfde object. Nu geldt regel twee: React behoudt het input-element en past enkel de value aan. De data die Veld nodig heeft, geef je door via props, hier naam en setNaam. Hetzelfde idee, dat functies en objecten enkel gelijk zijn als het om hetzelfde object gaat, komt straks terug onder de naam referentiële gelijkheid, bij React.memo en useCallback.
