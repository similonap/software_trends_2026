Framework-compilers

Een framework-compiler zet tijdens de build jouw componentcode om naar geoptimaliseerde JavaScript. Werk dat anders in de browser zou gebeuren, gebeurt nu vooraf.

Jij schrijft (Svelte)

let count = $state(0);

<button onclick={() => count++}>
  {count}
</button>

De compiler maakt ervan (vereenvoudigd)

button.addEventListener('click',
  () => set(count, count + 1));
effect(() => {
  text.data = get(count);
});

  • Ook: Angular-templates, React Compiler, Vue Vapor
  • Voordeel: kleinere, snellere runtime. Nadeel: build-stap nodig, moeilijker te debuggen

De derde strategie: een compiler. Een compiler zet code om van de ene vorm naar de andere. Een framework-compiler doet dat tijdens de build met je componenten: hij analyseert je code en genereert geoptimaliseerde JavaScript. Werk dat een framework anders tijdens het draaien in de browser zou moeten doen, gebeurt nu vooraf, op de machine van de developer of in de CI-pipeline. Kijk naar het voorbeeld. Links staat Svelte-code: een variabele count met dollar state, en een knop die count verhoogt en toont. Rechts staat, sterk vereenvoudigd, wat de Svelte-compiler daarvan maakt: een gewone event listener op de knop, en een effect dat de tekst van precies die ene tekstnode bijwerkt als count verandert. Er is geen virtual DOM en geen diffing in de browser nodig: de compiler wist al bij de build welke DOM-node van welke variabele afhangt. Je ziet ook dat de compiler intern signals gebruikt. Dat is typisch: compilers en signals worden vaak gecombineerd. Andere voorbeelden: Angular compileert zijn HTML-templates naar instructies. De React Compiler voegt automatisch memoization toe, zodat je geen useMemo meer hoeft te schrijven. En Vue Vapor Mode compileert Vue-templates naar directe DOM-operaties. Voordelen: de code die naar de browser gaat is kleiner en sneller, en jij schrijft eenvoudigere code. Nadelen: je hebt altijd een build-stap nodig, en wat de compiler doet is onzichtbaar; als er iets misgaat, debug je code die je niet zelf geschreven hebt. Samengevat hebben we nu drie strategieën: virtual DOM, signals en compilers. Op de volgende slide zien we welk framework welke combinatie gebruikt.
