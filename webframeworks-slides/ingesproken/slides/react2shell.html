Nu kunnen we begrijpen wat er op 3 december 2025 gebeurde. Het React-team maakte een kritieke kwetsbaarheid bekend in React Server Components, met nummer CVE-2025-55182, al snel React2Shell genoemd. De CVSS-score: tien, het maximum. Het probleem zat in de deserialisatie van het Flight-protocol. Een aanvaller kon één speciaal geconstrueerd HTTP-request naar de server sturen, en bij het omzetten van die data naar JavaScript-objecten kon hij de server zijn eigen code laten uitvoeren. Remote code execution, zonder in te loggen en zonder dat een gebruiker iets moest doen. En je hoefde zelf niet eens een Server Action geschreven te hebben: het volstond dat je app een kwetsbare React-versie met Server Components gebruikte. Jouw eigen authenticatie- en validatiecode hielp niet, want het lek zat in het framework, vóór jouw code. Kijk naar de tijdlijn. Het lek en de patch werden tegelijk gepubliceerd. Binnen vierentwintig uur zag het securitybedrijf Wiz al minstens vijftien verschillende groepen die het lek misbruikten, onder meer om cryptominers en botnets te installeren. Op 5 december zette het Amerikaanse cyberagentschap CISA het op de lijst van actief misbruikte kwetsbaarheden. Een week later vonden onderzoekers die de patch analyseerden nog twee extra lekken: een denial of service en het lekken van broncode. En half december draaide volgens Wiz nog ongeveer de helft van de publiek bereikbare kwetsbare servers zonder patch. Getroffen was niet alleen Next.js, maar elk framework dat RSC gebruikt. De les: Server Components zijn niet slecht, maar ze introduceren een nieuw protocol op de server, en een nieuw protocol heeft tijd nodig om veilig te worden. En een patch helpt alleen wie hem installeert.
