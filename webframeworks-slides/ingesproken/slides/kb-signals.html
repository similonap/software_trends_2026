Signals

Een signal is een reactieve waarde die bijhoudt wie ervan afhangt. Verandert de waarde, dan worden enkel die afhankelijke delen bijgewerkt (fine-grained reactivity).

const count = signal(0);
const double = computed(() => count() * 2);
effect(() => console.log(double()));

count.set(5); // logt 10

// template: <p>{{ double() }}</p>
// enkel deze tekstnode wordt aangepast

  • signal: schrijfbare waarde
  • computed: afgeleide waarde, automatisch herberekend en gecachet
  • effect: bijwerking die opnieuw draait bij een wijziging (bv. de DOM aanpassen)
  • Afhankelijkheden worden automatisch geregistreerd zodra je een signal leest

Kernbegrip

22

De tweede strategie: signals. Signals worden gebruikt door Angular, Solid, Svelte, Vue en Preact, elk met een eigen syntax, maar het principe is hetzelfde. Een signal is een waarde met een lijst van abonnees: iedereen die de waarde gelezen heeft, wordt verwittigd als ze verandert. Er zijn drie bouwstenen. Een signal is een schrijfbare waarde, hier count met beginwaarde nul. Een computed is een afgeleide waarde: double is altijd count maal twee. Een effect is code die opnieuw moet draaien als de waarden die ze gebruikt veranderen, bijvoorbeeld iets loggen of de DOM bijwerken. Het slimme zit in het automatisch registreren van afhankelijkheden, dependency tracking. Wanneer de computed-functie draait en count() leest, noteert het systeem: double hangt af van count. Je moet nergens zelf een lijst met dependencies schrijven, zoals bij useMemo in React. Als we daarna count op vijf zetten, weet het systeem precies dat double opnieuw berekend moet worden, en dat het effect opnieuw moet draaien: er wordt tien gelogd. In een template werkt dat net zo. Als je in een Angular-template double() toont, registreert dat stukje van de template zich als afhankelijke. Verandert count, dan wordt enkel die ene tekstnode aangepast. Er wordt geen volledige componentfunctie opnieuw uitgevoerd en er is geen boom om te vergelijken. Dat noemen we fine-grained reactivity: fijnmazige updates. Het verschil met de virtual DOM samengevat: bij de virtual DOM is de eenheid van update het component, en zoekt het framework achteraf uit wat er veranderd is. Bij signals is de eenheid de individuele waarde, en weet het framework op voorhand precies wat er moet gebeuren.
