Wat gebeurt er bij een klik op een link?

  • MPA (multi page application): de browser vraagt nieuwe HTML aan de server. Het scherm wordt even leeg en alle JavaScript-state is weg.
  • SPA (client-side routing): een JavaScript-router onderschept de klik, past de URL aan (History API) en toont meteen de nieuwe view. De data komt erna.
  • Server-gedreven (RSC): klik, request naar de server, de server rendert, de browser voegt het resultaat in. Zonder voorbereiding moet je wachten.

Prefetching = code of data voor een link al ophalen vóór de gebruiker klikt, bijvoorbeeld zodra de link in beeld komt of bij hover. De klik voelt dan onmiddellijk.

Wat gebeurt er eigenlijk als je op een link klikt? Er zijn drie modellen. In een klassieke multi-page application, een MPA, vraagt de browser een volledig nieuwe HTML-pagina aan de server. Het scherm wordt even leeg, de pagina wordt opnieuw opgebouwd, en alles wat JavaScript in het geheugen had, zoals een half ingevuld formulier, is weg. Zo werkte het web oorspronkelijk. In een single page application onderschept een JavaScript-router de klik. Die past de URL in de adresbalk aan via de History API van de browser, zonder de pagina te herladen, en toont meteen de nieuwe view, eventueel met een laadindicator. De data voor die view wordt daarna opgehaald. Omdat de code voor de volgende pagina al in de browser zit, voelt de navigatie onmiddellijk. In een server-gedreven app met Server Components zit de logica om de volgende pagina te renderen op de server. Bij een klik stuurt de browser een request, de server rendert de nieuwe pagina, en de browser voegt het resultaat in zonder volledig te herladen. Dat is efficiënt, maar als de server traag is of de verbinding traag, zie je na je klik even niets gebeuren. De oplossing daarvoor heet prefetching: de code of data voor een link al ophalen voordat de gebruiker klikt. Bijvoorbeeld zodra de link zichtbaar wordt op het scherm, of wanneer de muis erover beweegt. Op het moment van de klik ligt alles al klaar. Het nadeel: je haalt misschien dingen op die de gebruiker nooit bekijkt, wat extra netwerkverkeer en serverbelasting geeft. Dat spanningsveld tussen snel aanvoelen en niet te veel werk doen, komt zo meteen terug bij Next.js.
