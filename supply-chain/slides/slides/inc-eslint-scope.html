Incident · 12 juli 2018 · accountovername

eslint-scope: een hergebruikt wachtwoord

Toegang

De maintainer gebruikte een wachtwoord dat al in een ander datalek zat, en had geen 2FA. De aanvaller logde in en maakte een npm-token aan.

Verspreiding

eslint-scope@3.7.2 kwam via de gewone semver-range binnen, ook transitief via eslint zelf. Het package had ~2,3 mln downloads per week.

Payload

Een postinstall-script haalde code van pastebin.com, die ~/.npmrc met publicatietokens naar de aanvaller stuurde: tokens om verder te kunnen.

Detectie en respons

Een gebruiker meldde het na ongeveer een halfuur; npm haalde de versie na ~2 uur offline. Omdat tokens van ~4.500 accounts mogelijk gelekt waren, trok npm alle oudere tokens in.

Les. Eén hergebruikt wachtwoord zonder 2FA geeft toegang tot je hele achterban. Het idee achter Shai-Hulud bestond al in 2018.

Had dit tegengehouden

2FA, install scripts blokkeren

Deel 4 — Tijdlijn en casestudies · 0:18–0:30

Verdieping: sla over bij tijdgebrek. 12 juli 2018. Een maintainer van ESLint had op npm hetzelfde wachtwoord als bij een andere dienst die gelekt was, en geen 2FA. De aanvaller logde in, maakte een npm-token aan en publiceerde eslint-config-eslint@5.0.2 en eslint-scope@3.7.2. Het postinstall-script van eslint-scope haalde code op van pastebin.com. Die las ~/.npmrc, het bestand waarin npm je publicatietoken bewaart, en stuurde het naar de aanvaller. Met die tokens kon de aanvaller op zijn beurt de packages van de slachtoffers publiceren. Dat is precies het wormidee van Shai-Hulud, zeven jaar eerder. Tijdlijn (UTC): publicatie om 10:40, melding door een gebruiker om 11:17 (issue #39), unpublish door npm om 12:37. Volgens npm konden tokens van ongeveer 4.500 accounts buitgemaakt zijn. npm vond geen bewijs van misbruik, maar trok voor de zekerheid alle tokens in die vóór het incident waren aangemaakt. Les: hier volstond zelfs gewone 2FA. ESLint raadde achteraf ook lockfiles aan, en install scripts blokkeren had de payload tegengehouden. Bronnen: postmortem van ESLint; incidentrapport van npm (blog.npmjs.org, juli 2018).
