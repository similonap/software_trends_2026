Deel 5 — Verdediging als gebruiker · 0:30–0:36

Echte output van een project op npm 11. Sinds npm 11.16 (27 mei 2026) kent npm 11 de allowScripts-lijst al, maar alleen als advies: de install scripts draaien nog gewoon, en npm toont welke packages je nog niet beoordeelde. Met npm approve-scripts --allow-scripts-pending vraag je die lijst op zonder iets te wijzigen. Lees de lijst samen met de zaal. Drie packages bevatten native code met een binding.gyp. npm toont daarvoor het label node-gyp rebuild, al hebben ze in werkelijkheid een eigen install script dat eerst een kant-en-klare binary probeert (zie de slide over binding.gyp in deel 2). Bij esbuild en fsevents meldt npm alleen dat er een install script is, zonder de inhoud te tonen. Dit zijn de packages waarvan het script in npm 12 niet meer draait tot je het goedkeurt. Vanaf npm 11.18 (29 juni 2026) heten de commando’s npm install-scripts ls, npm install-scripts approve en npm install-scripts deny. De oude namen approve-scripts en deny-scripts blijven als alias werken, ook in npm 12. Migratietip voor studenten: draai dit op npm 11, keur alleen goed wat een script echt nodig heeft, en commit de allowScripts-lijst in package.json. Een goedkeuring wordt standaard als exacte versie vastgelegd (bijvoorbeeld esbuild@0.28.2), dus een nieuwe versie vraagt opnieuw om goedkeuring. Op npm 12 voer je na een goedkeuring npm rebuild uit, zodat het overgeslagen script alsnog draait. Vraag aan de zaal: “Welke van deze vijf zou je goedkeuren, en hoe beslis je dat?”
