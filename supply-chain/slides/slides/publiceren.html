Kernpunt deel 2

npm draait op transitief vertrouwen. Door één package te installeren, vertrouw je al zijn maintainers, hun accounts, hun pipelines en alle transitieve dependencies, en geef je hen codeuitvoering op je machine nog voor je één regel van hun code hebt gelezen.

Deel 2 — Hoe npm werkt · 0:05–0:12

Een maintainer logt in met npm login en publiceert met npm publish. De CLI bewaart een token in ~/.npmrc; in CI staat dat token als secret in de pipeline. Wie dat token heeft, is voor de registry de maintainer. Elke maintainer van een package kan elke versie publiceren, en één account beheert vaak tientallen packages. Eén gekaapt account geeft dus toegang tot veel packages tegelijk. De registry controleert bovendien niet of de tarball overeenkomt met de code op GitHub. Wat je op GitHub leest, is niet noodzakelijk wat je installeert. Bij event-stream zat de payload alleen in de geminificeerde tarball. In deel 6 komen we hierop terug met provenance. Lees het kernpunt voor; het is examenstof.
