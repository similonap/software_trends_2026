Vooruitblik

Veiligheid wordt de standaard

Staat sinds 2026 standaard aan

  • install scripts geblokkeerd: npm 12, pnpm, Yarn, Bun
  • een dag wachten in pnpm en Yarn, drie in Dependabot
  • de registry scant elke publicatie
  • staged publishing: een mens keurt de release goed

Daar schuiven aanvallers naartoe

  • code die pas bij import of in de browser draait
  • CI-pipelines en hun caches
  • misbruik van trusted publishing en provenance
  • de mens achter het account

Bij npm zet je de cooldown nog zelf aan (min-release-age), en alles hangt af van up-to-date tools.

Deel 7 — Geavanceerd en vooruitblik · 0:40–0:43

De grootste verschuiving van 2026 is dat veiligheid de standaard wordt: npm 12, pnpm 11 en Yarn 4.15 blokkeren install scripts, pnpm en Yarn houden nieuwe versies standaard een dag tegen (bij npm zet je dat zelf aan), Dependabot wacht drie dagen, de registry scant elke publicatie, en staged publishing brengt een mens terug in de lus. Aanvallers verschuiven daarom naar wat die standaarden niet dekken: code die pas bij import draait, CI-pipelines, misbruik van trusted publishing en, vooral, de mens achter het account. Kernpunt deel 7: de volgende stap in supply chain security is aantoonbaarheid. Weten wat je draait (SBOM), kunnen bewijzen hoe het gebouwd is (provenance, SLSA) en de schade kunnen beperken als het misgaat (isolatie). De Cyber Resilience Act maakt een deel daarvan verplicht: de meldplicht sinds september 2026, de SBOM vanaf december 2027.
