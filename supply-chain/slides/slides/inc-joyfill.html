Incident · 28 juli 2026 · code bij import

@joyfill: geen install script nodig

Toegang

Legitieme packages werden gekaapt; hoe is niet bekend. De kwaadaardige code zat alleen in de gepubliceerde tarballs, niet in de broncode op GitHub.

Verspreiding

Zes betaversies van @joyfill/components en @joyfill/layouts. Daarna paste de malware de globale npm-CLI aan, zodat elke volgende npm-opdracht hem opnieuw startte.

Payload

De code draaide bij import, niet bij installatie. Hij opende een kanaal voor toegang op afstand en installeerde een steler voor browsers, wallets en wachtwoordmanagers.

Detectie en respons

De AI-scan van StepSecurity markeerde de versie als kritiek, en een test in een sandbox bevestigde het.

Les. Install scripts blokkeren beschermt niet tegen code die in het package zelf zit en bij import draait.

Had dit tegengehouden

lockfile, cooldown, een gedragsscanner

Deel 5 — Verdediging als gebruiker · 0:30–0:36

Verdieping: de grens van laag 3. Sla over bij tijdgebrek. 28 juli 2026. Drie betaversies van @joyfill/components en drie van @joyfill/layouts bevatten kwaadaardige code. De code stond niet in de repository op GitHub, alleen in de tarballs op de registry. Wie de broncode reviewde, zag dus niets. Het verschil met bijna alle eerdere aanvallen: er is geen install script. StepSecurity: “The code runs when an application imports the package.” Dus ook op npm 12, met install scripts geblokkeerd, draait de code zodra je applicatie of je testsuite het package laadt. Payload: het C2-adres staat in blockchaintransacties (Tron, BNB Smart Chain, met Aptos als reserve). De malware opent een Socket.IO-kanaal waarmee de aanvaller code kan uitvoeren, bestanden kan lezen en je klembord kan zien, en installeert een Python-steler voor browsers, wallets, wachtwoordmanagers, git- en gh-credentials en de keychain. Daarna past ze de globale npm-CLI aan. StepSecurity: “Infection of the npm CLI is the supply-chain amplifier.” Alles wat je daarna op die machine bouwt of publiceert, kan besmet zijn. Wat helpt dan wel? Een lockfile met een vastgepinde stabiele versie (betaversies kwamen alleen binnen bij wie die expliciet vroeg), een cooldown, en scanners die naar het gedrag van de code kijken. Runtime-isolatie (deel 7) beperkt de schade. Bron: StepSecurity.
