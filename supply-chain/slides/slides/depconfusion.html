Hoe lekt de interne naam? Via een package.json in een publieke repo of in gebundelde JavaScript. Alex Birsan liet zo in 2021 code draaien bij meer dan 35 bedrijven.

# .npmrc: @acme komt altijd van de interne registry
@acme:registry=https://npm.intern.acme.example/

Verdediging: een eigen scope, vast gekoppeld, en een proxy die interne namen nooit publiek opzoekt.

Deel 3 — Het dreigingsmodel · 0:12–0:18

Dependency confusion kraakt geen enkel account en werkt toch. Bedrijven hebben interne packages, bijvoorbeeld acme-auth, op een private registry. Vaak staat daarvoor een proxy-registry (Verdaccio, Artifactory, GitHub Packages) die de interne packages en de publieke npm-registry samenvoegt tot één bron. Lekt de interne naam, via een package.json in een publieke repo of in gebundelde JavaScript, dan publiceert de aanvaller acme-auth@99.0.0 op de publieke registry. Een slecht geconfigureerde proxy levert dan gewoon de hoogste versie: die van de aanvaller. In februari 2021 liet onderzoeker Alex Birsan zo code draaien binnen meer dan 35 organisaties, waaronder Apple, Microsoft, PayPal en Netflix. Zijn payload was bewust onschuldig: een preinstall-script stuurde gebruikersnaam, hostnaam en pad door via DNS. Hij ontving meer dan 130.000 dollar aan bug bounties. De verdediging is eenvoudig: gebruik een scope die je zelf bezit, koppel die vast aan je private registry in .npmrc, en laat de proxy interne namen nooit publiek opzoeken.
