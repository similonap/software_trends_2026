Wat zegt npm audit?

$ npm audit  # ingekort
minimist  1.0.0 - 1.2.5
Severity: critical
Prototype Pollution in minimist
fix available via `npm audit fix`

nth-check  <2.0.1
Severity: high
Inefficient Regular Expression Complexity in nth-check
fix available via `npm audit fix --force`
Will install nth-check@3.0.1, which is a breaking change

2 vulnerabilities (1 high, 1 critical)

Hoe het werkt

Namen en versies uit je lockfile gaan naar de registry, die ze vergelijkt met de GitHub Advisory Database.

Ernst

low, moderate, high of critical. Met --audit-level kies je wanneer CI faalt.

Wat het niet ziet

De malware van vanmiddag: daar bestaat nog geen advisory voor.

Deel 5 — Verdediging als gebruiker · 0:30–0:36

Echte output van een klein testproject dat in zijn lockfile nog minimist 1.2.5 en nth-check 1.0.2 heeft (ingekort: de links naar de advisories zijn weggelaten). Hoe het werkt: npm audit stuurt de namen en versies van alle packages uit je lockfile naar de registry (het Bulk Advisory-endpoint). De registry vergelijkt ze met de GitHub Advisory Database en stuurt de gepubliceerde kwetsbaarheden terug, met hun ernst. Een package dat alleen kwetsbaar is omdat het een kwetsbare versie van een ander package vereist, heet een meta-vulnerability; npm volgt die ketting tot aan je eigen package.json. Lees de output samen: per kwetsbaarheid het getroffen versiebereik, de ernst en of er een oplossing is. Minimist kan npm zelf oplossen, nth-check alleen met --force. Twee kanttekeningen voor de zaal: - npm audit kent alleen gepubliceerde advisories. Tegen een kwaadaardige versie van vanmiddag helpt het niet; daarvoor dienen de cooldown en gedragsscanners. - Privacy: ook de namen van je interne packages gaan naar de registry. En de ruis: niet elke “high” is urgent. Een ReDoS in een build-tool die alleen je eigen bestanden leest, is zelden uit te buiten. Dan Abramov schreef daar in 2021 “npm audit: Broken by Design” over. Gebruik --omit=dev om devDependencies weg te filteren.
