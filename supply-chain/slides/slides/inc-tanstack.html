Incident · 11 mei 2026 · CI/CD-compromis en worm

TanStack: een vergiftigde cache

Toegang

Een pull request uit een fork startte een pull_request_target-job, die een vergiftigde pnpm-cache van 1,1 GB opsloeg onder een sleutel die de release-workflow op main later inlas.

Verspreiding

De code las het OIDC-token uit het geheugen van de runner en publiceerde 84 versies van 42 packages, met geldige provenance. Daarna besmette de worm UiPath, Mistral en anderen.

Payload

Een prepare-script startte onder Bun een steler voor cloud-, npm-, GitHub- en SSH-secrets. Persistentie via .claude/settings.json en .vscode/tasks.json.

Detectie en respons

StepSecurity opende 26 minuten na de eerste publicatie een issue; TanStack zelf had “no internal alerting”. Unit 42 telde die dag 373 versies van 169 packages.

Les. Provenance bewijst waar iets gebouwd is, niet dat de build proper was. En een CI-cache is ook invoer.

Deel 4 — Tijdlijn en casestudies · 0:18–0:30

Verdieping: sla over bij tijdgebrek. Dit is de leerrijkste aanval van 2026 voor wie zelf packages publiceert. TanStack maakt onder meer @tanstack/react-router, met meer dan 12,7 miljoen downloads per week. Op 11 mei 2026 opende een aanvaller pull request #7378 vanuit een fork. Die PR startte de workflow bundle-size.yml, die onder pull_request_target draaide: met de rechten van de basisrepository. De job sloeg een vergiftigde pnpm-cache van 1,1 GB op onder een cachesleutel die de echte release-workflow op main later herstelde. Uren later draaide release.yml. Die laadde de cache in, en de code van de aanvaller las het OIDC-token uit het geheugen van de runner. Om 19:20 en 19:26 UTC verschenen 84 versies van 42 packages. Geen enkel npm-token werd gestolen, en de packages droegen geldige provenance: ze waren aantoonbaar gebouwd in de officiële pipeline. StepSecurity: “SLSA provenance confirms which pipeline produced the artifact, not whether the pipeline was behaving as intended.” De payload stal secrets en nestelde zich in de configuratie van Claude Code en VS Code. Het token dat de malware aanmaakte, had als omschrijving “IfYouRevokeThisTokenItWillWipeTheComputerOfTheOwner”. Om 19:46 opende een onderzoeker van StepSecurity issue #7383. Tegen het einde van de dag telde Unit 42 373 kwaadaardige versies van 169 packages. GitHub reageerde: actions/checkout weigert sindsdien fork-code onder pull_request_target, en de Actions-cache is alleen-lezen voor onvertrouwde triggers. Bronnen: postmortem van TanStack; StepSecurity; Unit 42.
