Lifecycle scripts

Code die draait tijdens npm install

{
  "name": "handig-pakket",
  "version": "1.0.1",
  "scripts": {
    "postinstall": "node setup.js"
  }
}

Tot en met npm 11 draait dit automatisch, voor elke dependency in de boom, met jouw rechten. setup.js ziet:

  • je omgevingsvariabelen
  • ~/.npmrc, met je npm-token
  • ~/.ssh en je cloudcredentials
  • je browserprofielen

Nieuw sinds 8 juli 2026

npm 12 voert install scripts van dependencies alleen nog uit na goedkeuring. Bun, pnpm en Yarn gingen voor. Maar veel CI-images en tutorials draaien nog npm 10 of 11.

Deel 2 — Hoe npm werkt · 0:05–0:12

Hier zit de kern van het probleem. Een package kan in package.json scripts declareren die npm tot en met versie 11 automatisch uitvoert tijdens npm install, voor elke dependency in de boom: - preinstall, install en postinstall draaien bij elke installatie van dat package; - prepare draait onder meer bij dependencies die rechtstreeks uit een Git-repository komen; - bevat een package een binding.gyp-bestand, dan voert npm impliciet node-gyp rebuild uit, ook zonder scripts-sectie. Die scripts draaien met jouw rechten. Er zijn legitieme redenen voor (native modules compileren, een binary downloaden), maar de meeste aanvallen in deel 4 gebruikten dit mechanisme als startschot. Sinds juli 2026 voert npm 12 install scripts van dependencies niet langer automatisch uit. Bun voert al jaren alleen scripts van een lijst vertrouwde packages uit, pnpm stopte ermee in januari 2025 en Yarn in april 2026. Waarom blijft dit belangrijk? Veel CI-images, tutorials en bedrijfsprojecten draaien nog npm 10 of 11. Elk script dat je goedkeurt, draait daarna opnieuw met jouw rechten. En de meeste aanvallen in deel 4 rekenden op het oude gedrag.
