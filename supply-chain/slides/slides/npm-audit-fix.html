Deel 5 — Verdediging als gebruiker · 0:30–0:36

Wat doet npm audit fix? Het voert onder de motorkap een volledige npm install uit, en werkt elk kwetsbaar package bij naar een versie zonder advisory, maar alleen binnen de ranges van je package.json. In het testproject ging minimist in de lockfile van 1.2.5 naar 1.2.8; package.json bleef ongewijzigd. Voor nth-check bestaat geen oplossing binnen ^1.0.2, dus die bleef staan. npm audit fix --force mag ook buiten je ranges, tot een nieuwe major-versie. npm waarschuwt zelf: “using --force Recommended protections disabled” en “Updating nth-check to 3.0.1, which is a SemVer major change”. In het testproject veranderde package.json van ^1.0.2 naar ^3.0.1, en de transitieve dependency boolbase sprong mee van 1.0.0 naar 2.0.0. Een nieuwe major mag per definitie je code breken. Dus: eerst npm audit fix --force --dry-run, dan je tests. Zit een transitieve dependency vast, omdat een package dat jij gebruikt zelf een kwetsbare versie vereist? Dan wacht je op een nieuwe versie, stap je over op een alternatief, of dwing je met overrides in package.json een andere versie af. Dat laatste moet je goed testen. In CI: npm audit eindigt met een foutcode als het kwetsbaarheden vindt. --audit-level=high laat de build alleen falen vanaf high; het rapport zelf blijft volledig. --omit=dev laat devDependencies weg. De securityles: audit fix installeert nieuwe versies, en dus nieuwe code. Het houdt rekening met je cooldown (min-release-age) en op npm 12 met je allowScripts; sinds npm 11.18 waarschuwt npm als de cooldown een fix tegenhoudt. Lees de lockfile-diff in de pull request, net als bij elke andere update.
