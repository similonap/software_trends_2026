Deel 5 — Verdediging als gebruiker · 0:30–0:36

Laag 4, de juiste bron, tegen dependency confusion en typosquatting: - Zet alle interne packages onder een scope die je bezit, en registreer die organisatie ook op npmjs.com, zelfs als je er niets publiceert. - Koppel de scope vast aan je interne registry in .npmrc en laat je proxy-registry (Verdaccio, Artifactory, GitHub Packages) interne namen nooit upstream opzoeken. - Kopieer packagenamen uit de officiële documentatie. Controleer bij twijfel met npm view: hoe oud is het package, wie onderhoudt het, naar welke repository verwijst het? - Behandel een package dat een AI-assistent voorstelt als onbekend tot je zelf hebt nagegaan dat het bestaat en een geschiedenis heeft (slopsquatting). Laag 5, kijken: ken het verschil tussen tools die een databank opzoeken en tools die gedrag analyseren. npm audit vergelijkt met de GitHub Advisory Database; npm audit signatures verifieert registry-handtekeningen en provenance; Dependabot-malwarealerts (sinds maart 2026) en OSV-Scanner zoeken gekende kwaadaardige packages op; Socket analyseert code statisch op install scripts, obfuscatie, netwerk- en shellgebruik; Aikido Safe Chain is een lokale proxy die bekende malware blokkeert en standaard een minimumleeftijd van 48 uur afdwingt. De registry scant sinds 28 juli 2026 elke publicatie voordat ze installeerbaar wordt (meestal binnen een vijftal minuten). In september 2026 blokkeerde die scan bijvoorbeeld @nubjs/nub 0.9.4. Een slim signaal is vertrouwensverlies: met trustPolicy: no-downgrade weigert pnpm een versie die met minder bewijs gepubliceerd is dan haar voorgangers, bijvoorbeeld zonder trusted publishing terwijl eerdere versies dat wel hadden. Dat was precies het geval bij axios@1.14.1.
