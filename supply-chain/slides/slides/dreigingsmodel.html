Lees het diagram van boven naar onder: zes schakels van maintainer tot productie. Rechts staat bij elke schakel hoe een aanvaller binnenkomt, met echte voorbeelden. 1. Maintainer: phishing, accountovername en overname via vertrouwen (chalk/debug, eslint-scope, event-stream). 2. Broncode: een kwaadaardige bijdrage, zoals de backdoor in xz-utils na jarenlang opgebouwd vertrouwen. 3. Build en CI: workflow-injectie, gestolen CI-tokens, gekaapte Actions (Nx, tj-actions, TanStack). 4. Registry: misleidende namen en bronnen (crossenv, Birsan, PhantomRaven). 5. Installatie: install scripts die secrets stelen en zich verspreiden (ua-parser-js, Shai-Hulud, axios). 6. Productie: kwaadaardige code die bij je gebruikers draait (chalk/debug in de browser, polyfill.io). De gestippelde lijn links is de worm: Shai-Hulud gebruikte tokens die tijdens de installatie gestolen werden om nieuwe besmette versies op de registry te zetten. Zo voedt de keten zichzelf. Merk op: een aanvaller met een gestolen token springt van de maintainer meteen naar de registry. Wat je op GitHub leest, is niet noodzakelijk wat je installeert. Vraag aan de zaal: “Welke schakel controleer jij vandaag zelf?” Het eerlijke antwoord is meestal geen enkele. Gebruik dat als brug naar de casestudies.
