Incident · 3 juni 2026 · binding.gyp misbruikt

Phantom Gyp: een install script dat niet bestaat

Toegang

Gecompromitteerde maintaineraccounts, te beginnen met @vapi-ai/server-sdk (~86.500 downloads per week). Hoe die accounts gecompromitteerd werden, is niet bekend.

Verspreiding

Een worm: hij vroeg alle packages van de maintainer op, voegde binding.gyp en index.js toe en publiceerde ze opnieuw. 57 packages en 286 versies in minder dan twee uur.

Payload

Geen scripts in package.json. npm draaide zelf node-gyp rebuild, en de regel <!(node index.js) in binding.gyp startte een steler. Er werd niets gecompileerd.

Detectie en respons

Chainguard blokkeerde alle versies zes uur later. Snyk: de gestolen data is versleuteld, dus achteraf weet je niet wat er weg is.

Les. Een install script hoeft niet in package.json te staan: een bouwbestand voert net zo goed code uit.

Had dit tegengehouden

install scripts blokkeren, cooldown

Deel 2 — Hoe npm werkt · 0:05–0:12

Verdieping: dit is het bewijs bij de vorige slide. Sla over bij tijdgebrek. 3 juni 2026, 23:30 UTC: kwaadaardige versies van @vapi-ai/server-sdk verschijnen. Binnen twee uur volgen ai-sdk-ollama, 25 autotel-packages en de packages van nog een maintainer: 57 packages en meer dan 286 versies. StepSecurity gaf de techniek de naam Phantom Gyp, de campagne heet Miasma. Het mechanisme is precies wat we net zagen. package.json bevat geen enkel script. Maar het package heeft een binding.gyp in de root en geen eigen install script, dus npm voert zelf node-gyp rebuild uit. In binding.gyp staat een command expansion: <!(node index.js …). GYP voert die uit tijdens de configure-fase, nog voor er iets gecompileerd wordt. Het target heeft type “none”: er wordt helemaal niets gebouwd. De uitvoer gaat naar /dev/null, zodat de installatie er normaal uitziet. Wie alleen het scripts-veld van package.json controleert, met een scanner of een allowlist, ziet niets. Volgens Snyk blokkeert --ignore-scripts de impliciete node-gyp rebuild wel. Op npm 12 telt zo’n package ook als package met een install script, en dus moet je het eerst goedkeuren. Payload: een versluierde loader van 4,5 MB haalt Bun op en start een steler voor cloud-, CI-, Vault-, Kubernetes- en wachtwoordmanagergegevens, met persistentie in .claude/, .cursor/rules/ en .vscode/tasks.json. Snyk: “Do not treat a clean latest tag as evidence you are safe.” Bronnen: Snyk; Chainguard.
