Incident · 14 maart 2025 · CI/CD-compromis

tj-actions: een tag is geen belofte

Toegang

Een keten van gestolen tokens: een pull_request_target-workflow bij spotbugs lekte een token, dat via reviewdog uiteindelijk schrijfrechten op tj-actions/changed-files gaf.

Verspreiding

Bijna alle tags, van v1 tot v45, werden verlegd naar een kwaadaardige commit. Wie @v45 gebruikte, kreeg bij de volgende run nieuwe code. Meer dan 23.000 repositories gebruikten de action.

Payload

Een script las het geheugen van de runner uit en zette alle secrets base64-gecodeerd in de buildlog, die bij publieke repositories voor iedereen leesbaar is.

Detectie en respons

Harden-Runner van StepSecurity zag een onverwachte netwerkverbinding. GitHub blokkeerde de action de volgende dag. Volgens Endor Labs lekten 218 repositories echt secrets.

Les. Een tag kan de eigenaar, of een aanvaller, elk moment verleggen. Een commit-SHA niet.

Had dit tegengehouden

Actions op een commit-SHA pinnen

Deel 4 — Tijdlijn en casestudies · 0:18–0:30

Verdieping: sla over bij tijdgebrek. Dit is het voorbeeld bij regel 4 in deel 6: pin Actions op een SHA. tj-actions/changed-files is een populaire GitHub Action die bepaalt welke bestanden een pull request wijzigt. Op 14 maart 2025 verlegde een aanvaller bijna alle versietags, van v1 tot v45, naar één kwaadaardige commit, vermomd als een commit van renovate[bot]. Toegang: een keten. In december 2024 lekte een pull_request_target-workflow bij het project spotbugs een token. Daarmee kwam het token van een maintainer van reviewdog vrij, en via de action reviewdog/action-setup een token met schrijfrechten op tj-actions. Volgens Unit 42 was het eigenlijke doelwit coinbase/agentkit. Payload: een Python-script las het geheugen van het Runner.Worker-proces en drukte alle secrets dubbel base64-gecodeerd af in de buildlog. Unit 42: het “prints all of the credentials that were present in the CI runner's memory to the workflow's log”. Bij publieke repositories kan iedereen die logs lezen. Schaal: meer dan 23.000 repositories gebruikten de action. Endor Labs vond 614 repositories die de workflow in het venster draaiden, en 218 die echt secrets lekten, vooral kortlevende GITHUB_TOKENs. Repositories die de action op een commit-SHA hadden gepind, bleven onaangetast. Detectie: StepSecurity Harden-Runner zag een verbinding naar gist.githubusercontent.com die er niet hoorde. GitHub blokkeerde de action op 15 maart; CISA zette de kwetsbaarheid op de lijst van actief misbruikte kwetsbaarheden. Bronnen: Unit 42; Endor Labs; CISA; StepSecurity.
